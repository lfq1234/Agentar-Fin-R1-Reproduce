## 1. 背景与目标

当前 `01-前端` 已实现单会话聊天界面：用户提问、后端返回、消息流展示。但所有对话只存在于当前屏幕内存，点击「新对话」即清空，无法在多轮会话之间切换或回溯。

本期（**02-聊天历史侧边栏**）目标是在现有前端基础上新增：

1. **左侧边栏**：展示当前用户的聊天历史会话列表，支持切换、新建、删除。
2. **左上角「个人文档」入口**：一个固定卡片式入口，与 WorkBuddy 侧栏顶部的个人空间入口形态对齐，作为后续个人知识库 / 文档上传的导航锚点。

整体保持**最小改动**：不新增后端接口、不引入状态库 / UI 框架，会话数据先由前端本地维护；后续若需跨设备 / 刷新持久化，再接入后端 `03-传统后端基础层` 的会话列表接口。

## 2. 范围

### 2.1 包含（In Scope）

- 左侧固定侧边栏，宽度 240px（桌面），移动端可收起。
- 侧边栏顶部显示「个人文档」入口卡片。
- 侧边栏中部显示「历史会话」列表，含会话标题、最近活动时间、当前选中态。
- 点击历史会话切换右侧聊天上下文（消息流、当前 `conversation_id`、场景）。
- 提供「新对话」按钮，创建空白会话并切换到该会话。
- 提供删除历史会话按钮（ hover 显示，避免误触）。
- 会话标题自动取自该会话第一条用户消息的前 20 字（超出截断并附「…」省略号）；无用户消息时显示「新对话」。
- 本期会话仅存内存，**刷新即丢失并重置为单个空白会话**（MVP 不做服务端持久化）；URL/本地状态保持与刷新恢复为后续接入后端会话列表接口时的能力（见 §7 已知问题 1）。

### 2.2 排除（Out of Scope）

- 后端新增接口：本期复用现有 `/api/v1/chat` 与 `/api/v1/analyze`。
- 个人文档的具体功能（上传、解析、RAG 召回）：本期仅做入口卡片与占位面板。
- 跨设备同步、服务端持久化会话列表：后续可接 `GET /api/v1/conversations?user_id=`。
- 会话重命名、搜索、分组、置顶：超出本期最小可用范围。
- 拖拽排序。

## 3. 功能需求

### 目标 1 · 左侧聊天历史侧边栏

- 侧边栏常驻在界面左侧，背景色使用 `--panel`，与主区形成层次。
- 列表按会话「最近活动时间」倒序排列，最近活跃的会话在最上方。
- 每条会话展示：
  - 标题（自动提取，见目标 3）
  - 相对时间（如「刚刚」「5 分钟前」「昨天」）
- 当前激活会话高亮显示。
- hover 会话项时显示删除按钮；点击删除后移除该会话，若删除的是当前会话则自动切换到 updatedAt 最新的会话；无会话时自动创建一个空白会话。

### 目标 2 · 左上角「个人文档」入口

- 在侧边栏最顶部放置一个卡片式入口，左侧带文档图标，右侧文字为「个人文档」。
- 卡片高度约 40px，圆角、边框与主按钮风格一致。
- 点击后展开/切换右侧「个人文档」面板（MVP 内显示占位文案与后续扩展说明）。
- 当个人文档面板打开时，卡片高亮；再次点击或点击聊天区域时关闭。

### 目标 3 · 会话标题自动生成

- 会话标题 = 该会话中第一条用户消息的 `content.trim().slice(0, 20) + "…"`（超出 20 字截断并附省略号；不足 20 字原样）。
- 若会话无用户消息，标题显示「新对话」。
- 标题在发送第一条用户消息后即时更新，无需手动保存。

### 目标 4 · 会话切换与状态隔离

- 切换会话时，右侧聊天区立即渲染该会话的消息流。
- 每个会话独立维护：`history`、`conversationId`、`scene`、`createdAt`、`updatedAt`；场景 `scene` 与 `Header` 场景选择**双向绑定**（切换会话时回显该会话 scene，修改场景写入当前会话）。
- 切换会话不触发后端请求；仅在当前会话内发送消息时才调 `/api/v1/chat`，并携带当前会话已有的 `conversationId`（若有，复用后端上下文）。

### 目标 5 · 新对话

- 侧边栏底部提供「+ 新对话」按钮。
- 点击后创建空白会话并激活，右侧聊天区显示空提示。

### 目标 6 · 与个人文档的互斥

- 个人文档面板与聊天区互斥：打开个人文档时隐藏聊天区；关闭个人文档后恢复显示当前会话聊天区。
- 侧边栏历史会话列表在个人文档打开期间仍可操作；切换会话自动关闭个人文档并回到聊天区。

## 4. 接口契约

本期**不新增后端接口**，复用 `01-前端` 已对齐的契约：

- `GET /api/health`
- `POST /api/v1/chat`
- `POST /api/v1/analyze`

每个会话在发送消息时携带 `user_id`；若该会话已持有后端返回的 `conversation_id`，则一并携带以**复用后端会话上下文**（切换回已有会话再发送不会丢失历史）；新会话（无 `conversation_id`）不携带，由后端新建。不同会话之间的 `conversation_id` 相互隔离。

> **后续扩展（非本期）**：后端可提供 `GET /api/v1/conversations?user_id=` 拉取服务端会话列表，前端在初始化时合并本地与会话服务数据。

## 5. 数据模型

新增 `ChatSession`（前端本地状态）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `string` | 前端生成的唯一标识（如 `crypto.randomUUID()`） |
| `title` | `string` | 会话标题，自动计算 |
| `history` | `UiMessage[]` | 当前会话消息流 |
| `conversationId` | `number \| null` | 后端返回的会话 ID |
| `scene` | `SceneOption` | 当前会话场景 |
| `createdAt` | `number` | 创建时间戳 |
| `updatedAt` | `number` | 最近活动时间戳 |

`useChat` 返回值扩展：

- `sessions: ChatSession[]`
- `currentSessionId: string`
- `setCurrentSessionId: (id: string) => void`
- `createSession: () => string`
- `deleteSession: (id: string) => void`
- `personalDocsOpen: boolean`
- `setPersonalDocsOpen: (v: boolean) => void`

## 6. 验收标准

- [ ] 左侧边栏正常显示，宽度在桌面端固定 240px，移动端可收起（或自适应）。
- [ ] 左上角「个人文档」入口卡片可见，点击可展开/关闭个人文档占位面板。
- [ ] 历史会话列表按最近活动时间倒序排列。
- [ ] 点击历史会话可切换右侧聊天上下文，消息流、场景、conversation_id 正确隔离。
- [ ] 新对话按钮可创建空白会话并激活。
- [ ] 删除历史会话后列表即时更新；删除当前会话时自动切换到最近会话。
- [ ] 发送第一条用户消息后，会话标题自动更新。
- [ ] 不引入额外依赖（状态库 / UI 库 / HTTP 库）。
- [ ] 现有 `/api/v1/chat`、`/api/v1/analyze` 调用逻辑不被破坏。

1. **会话持久化**：本期会话列表仅存内存，刷新即丢失。后续可接后端 `GET /api/v1/conversations?user_id=` 与会话详情接口。
2. **个人文档功能**：本期仅做入口与占位面板，具体上传 / 解析 / RAG 召回在后续迭代实现。
3. **移动端交互**：侧边栏在窄屏下默认收起，需增加一个汉堡菜单触发；本期可在 MVP 中先保持桌面布局，后续再补响应式。
4. **标题长度**：固定 20 字截断；后续可考虑按语义断句或允许用户重命名。
