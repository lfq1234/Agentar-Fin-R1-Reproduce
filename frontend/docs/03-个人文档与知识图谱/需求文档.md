# 03 · 个人文档与知识图谱（需求文档）

> 版本：v1
> 状态：草稿（待实现后转「已落地」）
> 范围：`frontend/` 个人文档上传、管理与个人知识图谱可视化
> 关联：`00-总文档/00-总文档.md`、`01-前端/需求文档.md`、`01-前端/技术文档.md`、`02-聊天历史侧边栏/需求文档.md`

---

## 1. 本期目标

- 在前端「个人文档」面板内提供**用户文档上传**能力（PDF / DOCX / TXT / MD）。
- 展示已上传文档列表，支持**删除、解析状态查看**。
- 基于后端从文档中提取的实体与关系，绘制**个人知识图谱**（节点-边力导向图），类似下图交互形态：

  - 橙色节点：核心实体（如人名、机构、产品）。
  - 绿色节点：属性/值/地域等外围实体。
  - 边：带关系标签（如 `distribution area`、`belongs to`）。
  - 支持缩放、拖拽、点击高亮、悬停提示。

- 让图谱与对话联动：用户可选中节点/文档，将其摘要作为上下文带入当前会话。

---

## 2. 范围

### 2.1 范围内

- 个人文档上传 UI（拖拽区 + 文件选择）。
- 文档列表与状态展示。
- 个人知识图谱可视化组件。
- 图谱基础交互：缩放、平移、拖拽节点、点击高亮邻居、悬停提示。
- 图谱筛选：按实体类型、按来源文档。
- 图谱 → 当前会话的上下文注入（前端传递引用，后端最终消费）。

### 2.2 范围外（本期不做）

- 文档解析与实体抽取算法本身（由后端/模型完成）。
- 多用户权限、文档分享、云端存储。
- 复杂图布局算法自定义（本期用成熟力导向模拟）。
- 图谱编辑（增删节点/边）。
- 3D 图谱、时序图谱。

## 3. 功能需求

### FR1 · 个人文档上传

- 上传入口位于「个人文档」面板顶部。
- 支持点击选择文件与拖拽文件到上传区两种方式。
- 允许文件类型：`.pdf`、`.docx`、`.txt`、`.md`。
- 单文件大小上限 **20MB**；超出时前端即时提示，不上传。
- 单次可多选，最多 **10 个文件**。
- 上传过程中显示进度/加载态；上传完成后刷新文档列表。

### FR2 · 文档列表管理

- 列表展示：文件名、文件大小、上传时间、解析状态。
- 状态枚举：
  - `pending`：等待解析
  - `parsing`：解析中
  - `done`：已解析，可进入图谱
  - `error`：解析失败，显示错误原因
- 每个文档项提供：
  - 删除按钮（确认后删除）。
  - 失败时「重试」入口（可选，本期可只做删除后重新上传）。

### FR3 · 文档解析状态跟踪

- 上传成功后若状态为 `pending`/`parsing`，前端轮询 `GET /api/v1/documents/{id}/status`。
- 轮询间隔 2s，最多 60 次；超时后提示用户刷新重试。
- 全部文档解析完成后，自动刷新知识图谱。

### FR4 · 个人知识图谱展示

- 在个人文档面板内切换至「知识图谱」标签，展示全量图。
- 图元素：
  - 节点：实体（entity），含 `id`、`label`、`type`、`source_doc_id`。
  - 边：关系（relation），含 `source`、`target`、`label`。
- 节点按类型着色（至少 2 种颜色区分核心/外围实体，参考截图）。
- 边带文字标签，避免与节点重叠。
- 初始布局使用力导向模拟，稳定后渲染。

### FR5 · 图谱交互

- **缩放/平移**：鼠标滚轮缩放，拖拽画布平移。
- **拖拽节点**：可拖动节点调整位置，力导向继续微调。
- **点击节点**：高亮该节点及其一度邻居与边，其余元素置灰。
- **悬停节点/边**：显示 Tooltip（实体名称、类型、关系标签）。
- **双击节点**：打开右侧详情面板，展示该实体属性、来源文档、相关片段。
- **重置视图**：提供按钮恢复初始缩放与中心位置。

### FR6 · 图谱筛选

- 按实体类型筛选：复选框列表，勾选则显示该类型节点。
- 按来源文档筛选：下拉选择文档，仅显示来自该文档的节点与边。
- 筛选条件可组合；无匹配时显示空状态提示。

### FR7 · 图谱与对话联动

- 用户可点击「将选中实体带入对话」按钮，把当前高亮实体的摘要文本追加到当前会话上下文（或作为 system 提示）。
- 用户可在文档列表点击「基于此文档提问」，自动创建新会话并把文档摘要作为首条上下文。
- 前端仅负责传递引用/摘要；后端决定如何使用（RAG 检索或 prompt 注入）。

### FR8 · 响应式布局

- 桌面端：文档列表面板与图谱并排放置（左列表右图谱）。
- 窄屏（≤820px）：列表与图谱上下分屏，或标签切换。
- 图谱容器高度不低于 `400px`。

### FR9 · 空状态与错误处理

- 未上传文档时：展示空状态插画 + 「上传文档构建你的知识图谱」提示。
- 解析失败：文档项显示红色错误提示，可查看简要原因。
- 后端不可达：使用 `ErrorModal`（02 已引入）弹窗提示。

### FR10 · 权限与隔离

- 本期为单用户演示，默认 `user_id=1`。
- 所有文档/图谱接口均携带 `user_id`。
- 不实现登录、注册、多租户。

---

## 4. 非功能需求

- **依赖**：图谱可视化引入 **`@antv/g6`（v5）** 作为唯一新增依赖——国产、文档完善、辐射布局与 Canvas 渲染开箱即用；不再自研力导向或引入 `d3-force`。
- **性能**：单图节点数上限 500，边数上限 2000；超过时提示「文档过多，建议筛选」。
- **可访问性**：按钮带 `aria-label`，颜色对比度满足 WCAG 2.1 AA。
- **错误边界**：图谱组件崩溃不影响整个应用；显示「图谱渲染失败，请刷新」占位。

## 5. 数据模型与接口契约

> 注：以下后端接口为 03 前端需要消费的契约，需后端配套实现；如后端暂未实现，前端先做 Mock 数据联调。

### 5.1 前端类型

```ts
// types/agent.ts（新增）
export interface PersonalDocument {
  id: string;
  filename: string;
  size: number;        // bytes
  status: "pending" | "parsing" | "done" | "error";
  error?: string;
  uploadedAt: string;  // ISO 8601
}

export interface GraphNode {
  id: string;
  label: string;
  type: string;
  sourceDocId: string;
  // 可选：更多属性
  properties?: Record<string, string | number>;
}

export interface GraphEdge {
  id: string;
  source: string;   // node id
  target: string;   // node id
  label: string;
  sourceDocId: string;
}

export interface PersonalKnowledgeGraph {
  nodes: GraphNode[];
  edges: GraphEdge[];
}
```

### 5.2 后端接口契约（建议）

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| POST | `/api/v1/documents` | `multipart/form-data`：`files[]` + `user_id` | `{documents: PersonalDocument[]}` |
| GET | `/api/v1/documents` | `?user_id=1` | `{documents: PersonalDocument[]}` |
| DELETE | `/api/v1/documents/{id}` | `?user_id=1` | `{success: boolean}` |
| GET | `/api/v1/documents/{id}/status` | - | `PersonalDocument` |
| GET | `/api/v1/knowledge-graph` | `?user_id=1` | `PersonalKnowledgeGraph` |

- 所有路径统一带 `/api` 前缀，由 Vite 代理到后端 `:8000`。

## 6. 验收标准

- [ ] 可在「个人文档」面板完成 1 个 PDF + 1 个 TXT 上传，列表正确展示文件名、大小、状态。
- [ ] 解析完成后切换到「知识图谱」标签，能看到节点和边，节点按类型着色，边带标签。
- [ ] 可拖拽节点、滚轮缩放画布、点击节点高亮邻居。
- [ ] 按实体类型筛选后，未选中类型的节点隐藏，边同步隐藏。
- [ ] 选中节点后点击「带入对话」，当前会话输入框预填入相关摘要（或发送时附加）。
- [ ] 后端不可达时弹出 `ErrorModal` 提示。
- [ ] 移动端（≤820px）可正常上下分屏浏览。

## 7. 已知问题与风险

| 编号 | 问题 | 影响 | 缓解措施 |
| --- | --- | --- | --- |
| R1 | 后端暂无文档/图谱接口 | 阻塞真实数据 | 前端先用 Mock 数据跑通 UI；后端按 §5.2 接口契约实现后切换 |
| R2 | 大文档解析耗时长 | 用户体验差 | 上传后异步解析 + 轮询；提供解析进度提示 |
| R3 | 实体关系多导致图谱拥挤 | 可读性差 | 默认显示前 100 个核心节点；提供筛选/搜索 |
| R4 | 引入图谱库 `@antv/g6` 为额外依赖 | 与 01「轻量」原则冲突 | 已决策采用 G6 v5（评审 G2 闭环）：单一成熟依赖，换取开箱即用的辐射布局与 Canvas 渲染；自研力导向/ `d3-force` 方案被否决（效果差、工作量大）。 |
