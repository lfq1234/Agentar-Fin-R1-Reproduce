## 1. 总览

本模块在前端「个人文档」面板内实现：

1. **文档上传与管理**：拖拽/点击上传、列表展示、解析状态轮询、删除。
2. **个人知识图谱可视化**：基于后端返回的 `nodes`/`edges`，使用 **AntV G6（v5）** 渲染——内置 `radial`（辐射）力导向布局、Canvas 渲染与拖拽/缩放/高亮交互开箱即用，不再自研力导向或 SVG 渲染。

核心约束继承 01：

- Vite 5 + React 18 + TypeScript 5（strict）。
- 状态用 `useState` + 自定义 Hook。
- HTTP 用原生 `fetch`。
- 图谱可视化引入 **`@antv/g6`（v5，国产、文档完善、辐射布局开箱即用）** 作为唯一新增依赖，替代原先评估的 `d3-force` + 自研 SVG 方案（评审 G2/G3 的权衡结果，见 §11 决策）。

## 4. 关键组件

### 4.1 DocumentUploader

-  props：`onUpload: (files: FileList) => Promise<void>`, `uploading: boolean`
-  支持 `<input type="file" multiple accept="..." />` 与拖拽事件 `dragover/drop`。
-  文件校验：类型、大小、数量，失败即时 toast/提示（toast 用原生 DOM 或简单 state）。
-  上传时转 `FormData`：`files.append("files", file)` + `user_id=1`。

### 4.2 DocumentList / DocumentItem

- 列表按 `uploadedAt` 倒序。
- `status` 显示：pending（灰）、parsing（旋转）、done（绿）、error（红）。
- 解析中项启动轮询（`useEffect` + `setInterval`）。
- 删除二次确认：浏览器 `confirm` 即可（本期不引入弹窗库）。

### 4.3 KnowledgeGraphViewer

- 基于容器 `div`（`ref` 挂载点），内部由 **AntV G6** 渲染 Canvas。
- 仅初始化一次 `new Graph({...})`，数据变化通过 `graph.setData(data)` + `graph.render()` 重绘，不再自研力导向或 React+SVG tick。
- G6 配置要点：

```ts
import { Graph, GraphEvent } from "@antv/g6";

const graph = new Graph({
  container,
  autoResize: true,            // 跟随面板尺寸自适应
  layout: { type: "radial", unitRadius: 130, linkDistance: 130, preventOverlap: true },
  node: {
    type: "circle",
    style: {
      size: (d) => nodeRadius(d.data.type) * 2,   // 复用 utils/graph.ts 着色/半径
      fill: (d) => nodeColor(d.data.type),
      labelText: (d) => d.data.label,
      labelPlacement: "bottom",
    },
    state: { selected: {...}, active: {...}, inactive: {...} }, // 高亮态
  },
  edge: { type: "line", style: { endArrow: true, labelText: (d) => d.data.label } },
  behaviors: [
    "drag-canvas", "zoom-canvas",
    { type: "drag-element" },            // 拖拽节点
    { type: "hover-activate", degree: 1 }, // 悬停高亮一度邻居
    { type: "click-select", degree: 1 },   // 点击选中 + 邻居高亮
  ],
});
```

- 交互由 G6 行为内置，无需手写 transform/拖拽逻辑：
  - 缩放/平移：`zoom-canvas` / `drag-canvas`（缩放按钮经 `graph.zoomTo` / `graph.fitView` 接回）。
  - 节点拖拽：`drag-element`。
  - 高亮：`hover-activate`（悬停）+ `click-select`（点击）自动处理选中态与一度邻居。
- 业务事件：`node:dblclick` 打开 `EntityDetailPanel`；`node:pointerover` 显示 HTML tooltip；`GraphEvent.AFTER_TRANSFORM` 同步缩放比例显示。
- 筛选（按类型 / 来源文档）仍由上游 `useKnowledgeGraph` 完成，仅可见节点/边传入 `data`，与 G6 渲染解耦。

### 4.4 GraphControls

- 按钮：放大、缩小、重置、按类型筛选下拉、按文档筛选下拉。
- 位置：图谱右上角浮动。

### 4.5 EntityDetailPanel

- 双击节点或点击「详情」按钮后从右侧滑出。
- 展示：实体名、类型、来源文档、属性列表、相关片段、操作按钮「带入对话」。

### 5.2 useKnowledgeGraph

```ts
function useKnowledgeGraph() {
  const [graph, setGraph] = useState<PersonalKnowledgeGraph | null>(null);
  const [selectedTypes, setSelectedTypes] = useState<string[]>([]);
  const [selectedDocId, setSelectedDocId] = useState<string | "all">("all");

  const filteredNodes = useMemo(() => {
    return graph?.nodes.filter(n =>
      (selectedTypes.length === 0 || selectedTypes.includes(n.type)) &&
      (selectedDocId === "all" || n.sourceDocId === selectedDocId)
    ) ?? [];
  }, [graph, selectedTypes, selectedDocId]);

  return { graph, filteredNodes, selectedTypes, setSelectedTypes, selectedDocId, setSelectedDocId, fetchGraph };
}
```

## 7. API 客户端扩展

在 `src/api/client.ts` 中新增：

```ts
export async function uploadDocuments(files: File[]): Promise<PersonalDocument[]> {
  const form = new FormData();
  files.forEach(f => form.append("files", f));
  form.append("user_id", "1");
  const res = await fetch(`${BASE}/documents`, { method: "POST", body: form });
  if (!res.ok) throw new Error(`上传失败: ${res.status}`);
  return (await res.json()).documents;
}

export async function listDocuments(): Promise<PersonalDocument[]> {
  const res = await fetch(`${BASE}/documents?user_id=1`);
  if (!res.ok) throw new Error("获取文档列表失败");
  return (await res.json()).documents;
}

export async function deleteDocument(id: string): Promise<void> {
  const res = await fetch(`${BASE}/documents/${id}?user_id=1`, { method: "DELETE" });
  if (!res.ok) throw new Error("删除失败");
}

export async function getDocumentStatus(id: string): Promise<PersonalDocument> {
  const res = await fetch(`${BASE}/documents/${id}/status`);
  if (!res.ok) throw new Error("获取状态失败");
  return await res.json();
}

export async function getKnowledgeGraph(): Promise<PersonalKnowledgeGraph> {
  const res = await fetch(`${BASE}/knowledge-graph?user_id=1`);
  if (!res.ok) throw new Error("获取图谱失败");
  return await res.json();
}
```

## 11. 风险与替代方案

| 风险 | 说明 | 替代方案 |
| --- | --- | --- |
| 引入 `@antv/g6` 依赖 | 偏离 01「零额外依赖」原则（评审 G2） | 已决策：采用 G6 v5 作为唯一新增依赖，换取完善文档、开箱即用的辐射布局与 Canvas 渲染；自研力导向被否决（工作量高、效果差）。 |
| 大量节点卡顿 | 原 SVG+React tick 在 >200 节点即卡顿（评审 G3） | 已消解：G6 基于 Canvas 渲染，承载数千节点流畅；仅当节点 >1000 时给出「建议筛选」提示，与 FR6 筛选呼应。 |
| 后端接口未实现 | 阻塞真实数据 | Mock 数据先行；接口就绪后切换 |
| 移动端手势冲突 | 滚轮缩放与页面滚动冲突 | 移动端默认禁用缩放，仅允许按钮缩放 |

> **实现决策（2026-08-05）**：03 评审 G2/G3 通过「采用 AntV G6 v5」一并闭环——既是明确的依赖决策（G2），又用 Canvas 渲染消除了 200 节点上限矛盾（G3）。不再使用 `d3-force` 或自研 SVG 力导向。
