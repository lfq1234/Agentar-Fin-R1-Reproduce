## 1. 背景与目标

`Agentar-Fin-R1-Reproduce` 是复刻蚂蚁数科金融推理大模型的**全栈**工程（FastAPI 后端 + React 前端）。后端模块已落地：

- **01-模型接口**：统一模型调用入口（`app/model/`），`generate()` 直连 OpenAI 兼容端点。
- **02-多智能体基础框架**：`app/agent/system.py` 的 `run()` 串起「路由 → RAG → 专家作答 → 审核 → 风控 → 结构化分析」，返回 `AgentResult`。
- **03-传统后端基础层**：`app/routes/chat.py` 暴露 `POST /api/v1/chat`、`POST /api/v1/analyze`、`GET /api/health`，并以 **SQLite（异步 `aiosqlite`）** 可选落库。
- **04-专家智能体与工具 RAG**：各场景 prompts 与 RAG 检索增强。

本模块（**前端**）是这套全栈的**交互层**：一个 Vite + TypeScript + React 单页应用，通过 HTTP 调后端接口，向用户呈现「金融 Agent 问答 / 分析」能力，并验证意图识别、槽位填充、工具规划、表达生成等子能力。数据库由后端承载（SQLite），前端本身不直连数据库，仅消费后端返回的结构化数据。

**目标**：提供一个可运行、可演示、可联调的前端，使「用户提问 → 后端 Agent 处理（01/02）→ SQLite 落库（03，可选）→ 前端渲染」全链路可见。

## 2. 范围

### 2.1 包含（In Scope）

- 聊天交互界面：输入框、发送、加载态、回复展示。
- 场景选择：下拉选择金融场景（`Banking` / `Securities` / `Insurance` / `Trust` / `MutualFunds`），随请求带 `scene`。
- 会话连续性（**进阶 / 可选能力**）：消费后端返回的 `conversation_id`，续聊时随请求回传，展示历史消息。⚠️ **前提（非默认）**：后端 `config.yaml` 的 `db.enabled=true` **且** 每次请求带 `user_id`（默认 `1`）。因 `db.enabled` 默认 `false`，开箱演示下此能力不可达，仅作进阶演示（见 §3 目标 3）。
- 分析面板：调用 `/api/v1/analyze` 展示 `intent` / `slots` / `tool_plan` / `expression`。
- 合规与风险提示：渲染后端返回的 `compliance_notes` / `risk_flags`。
- 错误处理：网络 / 后端异常时友好提示；后端模型不可用时降级提示。
- 联调就绪：本地 dev server 通过 Vite 代理把前端请求转发到后端（默认 `:8000`），**路径前缀与后端保持一致（统一 `/api` 前缀）**。

### 2.2 排除（Out of Scope）

- 用户鉴权 / 多租户（后端 `user_id` 当前为请求体临时字段，非 token 解析）。
- 前端独立数据库 / 离线持久化（历史仅来自后端经接口返回）。
- 模型训练、Agent 编排、RAG 检索实现（属 01 / 02 / 04）。
- 流式（SSE）响应（本期后端为同步 JSON 响应）。

## 3. 功能需求

### 目标 1 · 聊天交互界面

- 提供消息输入框与「发送」按钮，支持回车发送。
- 发送后置「加载中」态，禁用重复提交；收到响应后展示 `reply`。
- 展示后端回传的 `compliance_notes`（合规建议）与 `risk_flags`（风险标记）列表。

### 目标 2 · 场景选择

- 提供场景下拉，枚举值需与后端 `app/agent/agents.py` 的 `SCENES` 对齐（当前：`Banking` / `Securities` / `Insurance` / `Trust` / `MutualFunds`）。
- 选中的 `scene` 随 `/api/v1/chat` 请求提交。**默认决策（已锁定，G3）**：前端默认发送 `scene="Banking"`（与当前 `App.tsx` 一致），即默认**不走** Coordinator 路由、直连 Banking 专家；为演示「路由 / 意图识别」子能力，场景下拉额外提供「自动路由」选项，选中时不传 `scene`，由后端 `app/agent/system.py` 的 `run()` 经 Coordinator 一次 LLM 调用判定场景（解析失败回退 `Banking`）。

### 目标 3 · 会话连续性（进阶 / 可选能力）

> ⚠️ **非默认能力（G2）**：本目标依赖后端 `db.enabled=true`（默认 `false`）**且** 前端每次 `chat` 携带 `user_id`（默认 `1`）。开箱默认状态下 `conversation_id` 恒为 `null`、无历史持久化，不计入默认验收必过项（见 §6）。实现时 `useChat` hook **必须默认 `user_id=1`**，否则静默无续聊。

- 首次请求不带 `conversation_id`；后端在「db 启用 + 传 `user_id`」时创建会话并返回 `conversation_id`。
- 前端保存该 `conversation_id`，后续同屏对话随请求回传，实现「续聊」。
- 展示当前会话的消息流（用户消息 + 助手回复），顺序按后端返回顺序。
- 支持「新对话」重置 `conversation_id` 与历史。

### 目标 4 · 分析面板

- 提供「分析」入口，调用 `POST /api/v1/analyze`（请求体 `{message, scene?}`）。
- 展示结构化结果：`intent`、`slots`（键值对）、`tool_plan`（列表）、`expression`。

### 目标 5 · 合规与风险提示

- `ChatResponse.compliance_notes` / `risk_flags` 以可读列表呈现（非仅原始 JSON）。
- 为空时优雅隐藏，不展示空区块。

### 目标 6 · 错误处理

- 网络不可达 / 后端 5xx 时，展示友好错误文案（`ErrorBanner`），不白屏。
- 后端因模型不可用返回错误（如 `ModelInvokeError`）时，提示「模型暂不可用，请检查后端配置」，并保留输入内容。

### 目标 7 · 联调就绪（前端侧）

- 本地 dev server 通过 Vite `server.proxy` 把请求转发到后端 `http://localhost:8000`。
- **请求路径前缀必须与后端一致**：后端暴露 `/api/v1/chat`、`/api/v1/analyze`、`/api/health`（**统一 `/api` 前缀**）；前端调用 `/api/v1/*`，Vite 代理配置为 `"/api" → "http://localhost:8000"`。
- 提供类型化的 API 客户端，请求 / 响应字段与后端契约（§4）对齐。

> **G1 决策反转（统一 `/api` 前缀）**：前后端一致采用 `/api` 前缀。后端 `include_router(prefix="/api")` 暴露 `/api/health`、`/api/v1/chat`、`/api/v1/analyze`；前端 `client.ts` `BASE="/api/v1"`、`health()` 调 `/api/health`、`vite.config.ts` 代理 `"/api"`。前端 `/api/v1/chat` 经代理命中后端 `/api/v1/chat`，无 404。

## 4. 接口契约（对齐后端 03，权威）

> 来源契约（已锁定）：后端 `app/db/models/conversation.py` 的 `ChatRequest` / `ChatResponse`，`app/db/models/message.py` 的 `AnalyzeRequest` / `AnalyzeResponse`，`app/routes/chat.py` 的路由。前端仅消费这些已文档化字段。

### 4.1 `GET /api/health`

- 请求：无。
- 响应（200）：`{ "status": "ok" }`

### 4.2 `POST /api/v1/chat`

请求体 `ChatRequest`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `message` | string | 是 | 用户问题（非空，`min_length=1`） |
| `scene` | string? | 否 | 金融场景；缺省由后端按默认 / Coordinator 路由处理 |
| `user_id` | int? | 否 | 临时方案：请求体携带；**续聊 / 落库需传**（`db.enabled=true` 时后端据此返回 `conversation_id`） |
| `conversation_id` | int? | 否 | 续聊时携带；首次为空 |

响应体 `ChatResponse`（200）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `scene` | string? | 回显会话级场景，便于前端对齐上下文 |
| `conversation_id` | int? | 会话 ID；「db 启用 且 传 `user_id`」时由后端创建返回，否则 `null` |
| `reply` | string | 助手主回复 |
| `compliance_notes` | string[] | 合规建议（建议式，不阻断） |
| `risk_flags` | string[] | 风险标记（建议式，不阻断） |

### 4.3 `POST /api/v1/analyze`

请求体 `AnalyzeRequest`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `message` | string | 是 | 待分析文本（非空） |
| `scene` | string? | 否 | 场景；缺省由后端按默认处理 |

响应体 `AnalyzeResponse`（200）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `scene` | string? | 回显被分析请求的场景 |
| `intent` | string? | 识别出的意图 |
| `slots` | object<string,string> | 槽位填充 |
| `tool_plan` | string[] | 工具调用计划 |
| `expression` | string | 表达 / 话术建议 |

> **数据库说明**：后端使用 SQLite（`config.db.type=sqlite`，异步驱动 `aiosqlite`，库文件默认 `./agentar.db`，相对 `backend/` 运行目录）。`db.enabled` 默认 `false`——默认情况下系统无库也能启动并响应，但此时 `chat` 不返回 `conversation_id`、无历史持久化。会话与消息由后端在 `db.enabled=true` 时落库；前端不感知具体表结构，仅通过 `conversation_id` 关联。

## 5. 配置

### 5.1 前端（Vite）

- `vite.config.ts` 的 `server.proxy`：把前端请求前缀转发到后端。
  - **采用**：`"/api"` → `"http://localhost:8000"`（前后端统一 `/api` 前缀，与后端 `include_router(prefix="/api")` 对齐）。
- API base：开发期经代理，无需硬编码主机；生产构建可经环境变量注入后端地址（如需跨域部署）。

### 5.2 后端（SQLite，续聊 / 落库时）

- `config/config.yaml` 的 `db` 段：`enabled: true`、`type: sqlite`、`sqlite_path: ./agentar.db`（可选）。
- `server.cors`：开发期默认 `allow_origins: ["*"]`；生产应显式放行前端 origin。
- 前端需在 `chat` 请求体携带 `user_id`（默认 `1`），后端才会返回 `conversation_id` 并落库。

- [ ] 前端可启动（`npm install && npm run dev`，默认 `:5173`）。
- [ ] 首页提供消息输入、发送、场景选择、分析入口。
- [ ] `POST /api/v1/chat` 经代理到达后端，渲染 `reply`；`compliance_notes` / `risk_flags` 正确展示。
- [ ] 续聊（**进阶项**：仅当后端 `db.enabled=true` 且前端传 `user_id` 时验证）：第二次请求携带首次返回的 `conversation_id`，后端按同一会话处理。
- [ ] `POST /api/v1/analyze` 渲染 `intent` / `slots` / `tool_plan` / `expression`。
- [ ] 后端不可用 / 模型不可用时，前端展示友好错误（`ErrorBanner`），不白屏。
- [ ] 🔴 请求路径前缀与后端一致（统一 `/api` 前缀）—— 前端 `BASE="/api/v1"` + 代理 `"/api"` 与后端 `include_router(prefix="/api")` 对齐。
- [ ] 前端类型化 API 客户端字段与 §4 契约一致。
- [ ] 联调时后端以 SQLite 落库：可在 `agentar.db` 查到 `users` / `conversations` / `messages` 记录（启用时）。

3. **场景枚举对齐（已一致）+ 默认场景决策锁定（G3）**：前端 `SCENES` 与后端 `app/agent/agents.py` 的 `SCENES` 已一致；默认发送 `Banking`、另增「自动路由」选项（不传 scene 触发后端 Coordinator 路由），见需求 §3 目标 2。

6. **生产代理**：仅 dev 有 proxy；生产需 docker-compose 或静态托管 + 反向代理暴露 `/api`。
