## 1. 总览

本模块是 `Agentar-Fin-R1-Reproduce` 全栈的**前端交互层**。技术栈与决策：

- **构建工具**：Vite 5（SPA，提供 dev server + 代理 + 生产构建）。
- **语言**：TypeScript 5（`strict` 严格模式）。
- **视图层**：React 18（脚手架已就绪；本期不更换框架）。
- **状态管理**：仅用 React 内置 `useState` + 自定义 Hook，不引入 Redux / Zustand。
- **HTTP**：浏览器原生 `fetch`，不引入 Axios / React Query。
- **样式**：原生 CSS（`index.css` 全局 + 组件级 className），不引入 UI 框架，保持轻量可演示。

数据流：

```
frontend(:5173)  --/v1/*-->  [Vite proxy]  -->  backend(:8000)  --应用-->  01 模型 / 02 Agent  -->  (可选) SQLite 落库
```

**关键事实（已核对后端源码，权威）**：

- 后端路由（`backend/app/routes/chat.py`）暴露：`GET /api/health`、`POST /api/v1/chat`、`POST /api/v1/analyze`，**统一带 `/api` 前缀**（由 `app/main.py` 的 `include_router(prefix="/api")` 挂载）。
- 后端经 `app/main.py` 的 `include_router(prefix="/api")` 挂载，所有接口统一前缀 `/api`。
- 响应契约见 §5 与 `01-前端/需求文档.md §4`。
- 续聊/落库前提：后端 `db.enabled` 默认 `false`，且 `chat` 仅在「db 可用 且 传入 `user_id`」时返回 `conversation_id` 并落库（详见 §8 注意）。

## 5. API 客户端设计（`src/api/client.ts` + `src/types/agent.ts`）

将后端契约镜像为 TS 类型，避免字段漂移。

`src/types/agent.ts`：

```ts
export type Scene = "Banking" | "Securities" | "Insurance" | "Trust" | "MutualFunds";
export const SCENES: Scene[] = ["Banking", "Securities", "Insurance", "Trust", "MutualFunds"];

export interface ChatRequest {
  message: string;
  scene?: Scene;
  user_id?: number;        // 后端落库 / 续聊需要；不传则 conversation_id 为 null
  conversation_id?: number;
}
export interface ChatResponse {
  scene?: Scene;
  conversation_id?: number | null;
  reply: string;
  compliance_notes: string[];
  risk_flags: string[];
}
export interface AnalyzeRequest {
  message: string;
  scene?: Scene;
}
export interface AnalyzeResponse {
  scene?: Scene;
  intent?: string | null;
  slots: Record<string, string>;
  tool_plan: string[];
  expression: string;
}
```

`src/api/client.ts`：

```ts
import type { ChatRequest, ChatResponse, AnalyzeRequest, AnalyzeResponse } from "../types/agent";

const BASE = "/api/v1"; // 经 Vite proxy 转发到后端 :8000（统一带 /api 前缀：vite proxy "/api" → 后端 :8000）

export class ApiError extends Error {
  constructor(public status: number, message: string) {
    super(message);
    this.name = "ApiError";
  }
}

async function post<T>(path: string, body: unknown): Promise<T> {
  let res: Response;
  try {
    res = await fetch(`${BASE}${path}`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(body),
    });
  } catch (e) {
    // 网络不可达 / 后端未启动：status=0 便于组件层区分
    throw new ApiError(0, `网络错误，无法连接后端：${(e as Error).message}`);
  }
  if (!res.ok) {
    // 422 = 字段校验（如 message 为空）；4xx = 客户端；5xx = 后端故障
    const detail = await res.text().catch(() => "");
    throw new ApiError(res.status, `请求失败 (${res.status})${detail ? "：" + detail : ""}`);
  }
  return res.json() as Promise<T>;
}

export const chat = (req: ChatRequest) => post<ChatResponse>("/chat", req);
export const analyze = (req: AnalyzeRequest) => post<AnalyzeResponse>("/analyze", req);
export async function health(): Promise<{ status: string }> {
  // 健康检查挂载在 /api 前缀下（与 chat/analyze 的 /api/v1 区分）。
  const res = await fetch("/api/health");
  if (!res.ok) throw new ApiError(res.status, `健康检查失败 (${res.status})`);
  return res.json();
}
```

要点：

- `BASE = "/api/v1"`，与后端路径一致（前后端统一 `/api` 前缀；G1 决策反转：采用 `/api`，后端 `include_router(prefix="/api")`）。
- 错误统一抛 `ApiError(status, message)`：网络故障 `status=0`；后端 422=字段校验（如 `message` 为空，前端 `ChatInput`/`AnalyzePanel` 已加 `trim()` 防护）、4xx=客户端、5xx=后端故障；组件层按 `status` 展示不同 `ErrorBanner` 文案（S3）。
- **默认场景（G3）**：`ChatRequest.scene` 为可选；`useChat` 默认发 `"Banking"`，场景下拉「自动路由」项对应 `scene` 不传（omit），由后端 Coordinator 路由（`app/agent/system.py` 的 `run()`）。

## 6. 组件设计

布局（建议单栏响应式 + 右侧分析抽屉）：

- **Header**：标题「Agentar-Fin-R1 复现 · 交互演示」+ 场景下拉（`SceneSelect`）+「新对话」按钮。
- **主区 MessageList**：按时间展示 user / assistant 气泡；助手气泡下方挂 `ComplianceRisk`（合规/风险，为空隐藏）。
- **底部 ChatInput**：文本输入 + 发送（回车发送，加载态禁用）。
- **分析（入口统一，S4）**：提供全局「分析」按钮（非每条消息内嵌），点击对**当前选中 / 最近一条助手回复**调 `/api/v1/analyze` → `AnalyzePanel` 以区块展示 `intent` / `slots` / `tool_plan` / `expression`。
- **ErrorBanner**：网络 / 后端异常时顶部提示条，不白屏。

组件职责：

| 组件 | 职责 |
| --- | --- |
| `Header` | 标题、场景选择、新对话重置 |
| `SceneSelect` | 场景下拉，枚举来自 `SCENES` |
| `MessageList` / `MessageBubble` | 消息流渲染 |
| `ChatInput` | 输入 + 发送（回车） |
| `AnalyzePanel` | 结构化分析四字段分块展示 |
| `ComplianceRisk` | 合规提示 / 风险标记列表 |
| `ErrorBanner` | 错误展示 |

渲染规则：

- `ChatResponse.reply` 作为助手消息追加到 `history`。
- `compliance_notes` / `risk_flags` 以列表展示；为空则隐藏对应区块。
- `AnalyzeResponse` 的 `intent` / `slots` / `tool_plan` / `expression` 分块展示（见需求 §3 目标 4）。

## 7. 状态管理（`src/hooks/useChat.ts`）

用自定义 Hook 封装，避免 `App.tsx` 臃肿。状态：

| 状态 | 类型 | 说明 |
| --- | --- | --- |
| `message` | `string` | 输入框内容 |
| `scene` | `Scene` | 当前场景（默认 `Banking`） |
| `conversationId` | `number?` | 续聊 ID；`null` = 新对话 |
| `userId` | `number` | **默认 `1`（落库 / 续聊必须，见 §8 注意 / G2）**——实现时务必随每次 `chat` 请求携带，否则静默无续聊 |
| `history` | `{role, content, compliance?, risk?}[]` | 当前会话消息流 |
| `analyzing` | `boolean` | 分析面板加载态 |
| `analyzeResult` | `AnalyzeResponse?` | 分析结果 |
| `loading` | `boolean` | 发送加载态 |
| `error` | `string?` | 错误提示 |

续聊逻辑：

- 首次 `chat()` 不带 `conversation_id`，但**始终携带 `user_id=1`** → 后端创建会话并返回 `conversation_id`（需 db 启用且传 `user_id`）→ 写入状态。
- 后续同屏对话随请求回传 `conversation_id`，实现「续聊」。
- 「新对话」按钮重置 `conversationId = null`。
- 历史消息仅前端内存维护（来源为后端返回）；不做前端独立持久化（排除项见需求 §2.2）。

## 8. 代理与跨域

- **Vite dev proxy（G1 决策反转）**：前后端统一带 `/api` 前缀。后端 `app/main.py` 以 `include_router(prefix="/api")` 挂载，路由为 `/api/health`、`/api/v1/chat`、`/api/v1/analyze`；前端 `BASE="/api/v1"`、`health()` 调 `/api/health`、`vite.config.ts` 代理 `"/api" → :8000`。前端 `/api/v1/chat` 经代理命中后端 `/api/v1/chat`，无 404。
- **后端 CORS**：读取 `config.server.cors`，默认 `allow_origins=["*"]`，开发期足够；生产应显式放行前端 origin。
- **生产构建**：`vite build` → `dist/`，由 `Dockerfile` 产出，docker-compose 与后端同网部署；生产若跨域需反向代理暴露 `/api`。
- **注意（落库 / 续聊前提）**：后端 `db.enabled` 默认 `false`，且 `chat_service` 仅在「`db is not None` 且 `req.user_id is not None`」时返回 `conversation_id` 并落库。因此前端续聊功能需同时满足：① 后端 `config.yaml` 设 `db.enabled: true`；② 前端每次 `chat` 携带 `user_id`（默认 `1`）。否则 `conversation_id` 恒为 `null`、无历史持久化。需求文档已据此明确。

## 9. 联调方案（实现后按此执行）

> 本轮（v1）仅产出文档；以下为**联调执行手册**，实现后起服务时按此执行。

1. **后端**：`cd backend && uvicorn app.main:app --reload --port 8000`；`curl http://localhost:8000/api/health` → `{"status":"ok"}`。如需续聊/落库，先设 `config.yaml` 的 `db.enabled: true`。
2. **前端**：`cd frontend && npm install && npm run dev` → `:5173`；确认 proxy 为 `/api`。
3. **验证清单**：
   - 发送问题 + 场景 → `POST /api/v1/chat` → 渲染 `reply` + `compliance_notes` / `risk_flags`。
   - 续聊：第二次请求带首次返回的 `conversation_id`（需后端 db 启用 + `user_id`），后端按同会话处理。
   - 点「分析」→ `POST /api/v1/analyze` → 渲染 `intent` / `slots` / `tool_plan` / `expression`。
   - 模型不可用 → `ErrorBanner` 友好提示，不白屏。
