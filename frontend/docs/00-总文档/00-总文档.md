## 1. 本期目标（01-前端）

- 为 `Agentar-Fin-R1-Reproduce` 全栈建立前端交互层：Vite 5 + TypeScript 5 + React 18 单页应用。
- 通过 HTTP 消费后端 `03-传统后端基础层` 的 `/api/v1/chat`、`/api/v1/analyze`、`/api/health` 接口。
- 呈现金融 Agent 的「问答 / 分析」能力，验证意图识别、槽位填充、工具规划、表达生成等子能力。
- 本期不做：鉴权 / 多租户、前端独立数据库、模型训练 / Agent 编排 / RAG 实现、SSE 流式（详见 `01-前端/需求文档.md §2.2`）。

### 2.2 技术栈与关键决策

- 构建：Vite 5；语言：TypeScript 5（`strict`）；视图：React 18。
- 状态用 `useState` + 自定义 Hook；HTTP 用原生 `fetch`；样式用原生 CSS。不引入额外状态 / HTTP / UI 库。
- 请求路径前缀 `/api`（**统一 `/api` 前缀**），Vite 代理 `"/api" → http://localhost:8000`。

### 2.3 接口契约（权威，已核对后端源码）

- `GET /api/health` → `{"status":"ok"}`
- `POST /api/v1/chat`：`ChatRequest{message, scene?, user_id?, conversation_id?}` → `ChatResponse{scene?, conversation_id?, reply, compliance_notes[], risk_flags[]}`
- `POST /api/v1/analyze`：`AnalyzeRequest{message, scene?}` → `AnalyzeResponse{scene?, intent?, slots{}, tool_plan[], expression}`
- **续聊 / 落库前提**：后端 `db.enabled=true`（默认 `false`）且 `chat` 请求带 `user_id` 时，才返回 `conversation_id` 并写 SQLite。

### 2.4 与各后端模块的关系

| 后端模块 | 与前端的关系 |
| --- | --- |
| `01-模型接口` | 提供 `run` 背后的模型调用（前端不直连） |
| `02-多智能体基础框架` | `app/agent/system.py` 的 `run()` 返回 `AgentResult`（前端消费的字段来源） |
| `03-传统后端基础层` | `/api/v1/chat`、`/api/v1/analyze`、`/api/health` 接口与 SQLite 落库（前端直接消费） |
| `04-专家智能体与工具 RAG` | 各场景 prompts 与 RAG 检索增强（前端仅通过 `scene` 间接触发） |
