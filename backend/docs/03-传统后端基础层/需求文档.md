# 需求文档 · 传统后端基础层（DB + Services + Routers + Main）

## 1. 背景与诉求

前序模块已就位（规划层面）：
- **01-模型接口**：API / 本地双模式统一入口 `get_model()`。
- **02-多智能体基础框架**：AgentScope 多智能体框架，主体位于 `app/agent/`，对外暴露 `async run(message, scene, structured) -> AgentResult`（含 `reply` / `compliance_notes` / `risk_flags` / 结构化四字段）。

但当前后端只有骨架：`routes/chat.py`、`services/inference.py` 是 stub，且没有真正的数据库与启动装配。本需求搭建**传统后端基础层**——把 02 的框架通过标准 FastAPI + SQLAlchemy 链路对外提供服务并持久化，是"把 AgentScope 框架接进工程化后端"的那一层。

> 注意：03 是**消费方**，不重新实现多智能体逻辑；它调用 02 的 `app/agent.run()`，只负责 HTTP 接入、业务编排与落库。

## 2. 目标与范围

- 目标 1（DB 层）：建立 SQLAlchemy 引擎 / 会话管理、ORM 模型（`User` / `Conversation` / `Message`），以及基础建表 SQL 文档 `app/db/schema.sql`；由 `config.db.enabled` 门控，未启用时整体跳过。
- 目标 2（Services 层）：封装 `chat` / `analyze` 服务，调用 02 的 `app/agent.run()`，并把会话与消息落库。
- 目标 3（Routers 层）：传统 REST 接口 `/health`、`/v1/chat`、`/v1/analyze`。
- 目标 4（Main）：传统 FastAPI 启动——`lifespan` 内加载配置 +（按需）初始化 DB、注册 CORS（取自 `config.server.cors`）、挂载路由。
- 目标 5（SQL 文档）：`app/db/schema.sql` 作为基础数据库新建文档（含 users / conversations / messages 三张核心表 + agent_traces 预留）。

**不在本次范围（后续独立需求）**：
- 鉴权 / 多租户（用户表先留最小字段，不接登录）。
- 真实 RAG 向量库（02 占位，检索后端后续）。
- `agent_trace` 轨迹采集与存储（表结构预留，03 不写）。
- SSE 流式响应（后续需求）。
- 02 框架本身的实现（属 02 编码阶段）。

## 3. 功能 / 非功能要求

- 功能点：
  - **DB 层**（`app/db/`）：
    - `session.py`：`engine` / `SessionLocal` / `get_db` 依赖；`init_db()` 在 `db.enabled` 时 `create_all`（开发期由 schema.sql 或 ORM 建表二选一，本需求以 ORM `create_all` 为主、schema.sql 作人工/生产建表参考）。
    - `models.py`：`User` / `Conversation` / `Message` ORM。
    - `schema.sql`：数据库新建设计文档（表结构与字段规划 + SQLite 适配说明，不含可执行 DDL）。
  - **Services 层**（`app/services/`）：
    - `chat_service.py`：`async chat(message, scene, user_id, conversation_id=None)` → 调 `app/agent.run()` 得 `AgentResult`，落库用户消息 + 助手消息，返回 `reply`（及建议式 `compliance_notes` / `risk_flags`）。
    - `analyze_service.py`（或并入 chat_service）：`async analyze(message, scene)` → 调 `run(structured=True)`，返回结构化四字段。
  - **Routers 层**（`app/routes/`）：
    - `chat.py`：`GET /health`、`POST /v1/chat`、`POST /v1/analyze`（均为传统 `async def` + `Depends(get_db)`）。
    - `__init__.py`：聚合 `APIRouter`。
  - **Main**（`app/main.py`）：`lifespan` 启动钩子、`FastAPI()` 实例、CORS、`include_router`。
- 非功能：
  - 复用 01 / 02：模型切换（`model.mode`）、agent 框架对 03 透明。
  - `db.enabled=false` 时：DB 相关调用短路（内存态 / 不落库），服务仍可用。
  - 可测性：`/health` 断言；`/v1/chat` 在 `db.enabled=false` 或无模型 key 时可 `skip` 真实调用。

## 4. 验收标准

- [ ] `app/db/` 含 `session.py`（引擎/会话/`get_db`/`init_db`）、`models.py`（User/Conversation/Message）、`schema.sql`（三张核心表 + agent_traces 预留 + SQLite 适配说明）。
- [ ] `app/services/` 含 chat / analyze 服务，调用 02 的 `app/agent.run()` 并落库会话与消息。
- [ ] `app/routes/chat.py` 提供 `/health`、`/v1/chat`、`/v1/analyze`，为传统 REST（async + `Depends(get_db)`）。
- [ ] `app/main.py` 为传统启动：`lifespan` 加载配置 +（启用时）初始化 DB、注册 CORS、挂载路由。
- [ ] `config.db.enabled=false` 时整体不依赖数据库即可启动并响应 `/v1/chat`。
- [ ] `pytest`：无 `OPENAI_API_KEY`、无 vLLM、`db.enabled=false` 时 `/health` 与（skip 真实的）`/v1/chat` 仍能跑。
