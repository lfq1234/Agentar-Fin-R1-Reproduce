## 1. 本期目标（01-模型接口）

- 在 `app/model/` 建立统一模型调用入口，对外暴露抽象 `ModelInterface`。
- 支持 API（云端 OpenAI 兼容）与本地（vLLM）两种模式，**物理分离、配置切换、工厂分发**。
- 上层（未来 `services/`）只依赖抽象接口，不感知具体模式。
- 本期不做：AgentScope 多 Agent 编排、SSE 流式、`db` 持久化（详见 01 需求文档排除项）。

## 2. 本期完成内容

### 2.1 目录结构（本期落地）
```
app/model/
├── __init__.py            # 导出 ModelInterface, ModelConfig, get_model, ModelInvokeError
├── base.py                # ModelInterface(abc) + ModelConfig(dataclass)
├── exceptions.py          # ModelInvokeError：统一异常
├── factory.py             # get_model()：校验 mode + 合并全局默认 + 返回实现
├── api/
│   ├── __init__.py
│   └── openai_api.py      # ApiModel
└── local/
    ├── __init__.py
    └── vllm_local.py      # LocalModel
```

### 2.2 抽象接口与配置
- `ModelInterface`：`build_agentscope_config() -> dict`、`generate(prompt, **kw) -> str`。
- `ModelConfig`：`model_type` / `model_name` / `api_key` / `base_url` / `temperature` / `stream` / `timeout` / `max_retries`。
- `ModelInvokeError`：统一异常，key 缺失 / 网络错误 / 超时 时抛出。

### 2.3 工厂分发（get_model）
- 校验 `model.mode ∈ {api, local}`，非法值抛 `ValueError`。
- 合并顶层全局默认 `timeout` / `max_retries` 到所选子段（子段优先）。
- 按 mode 返回 `ApiModel` / `LocalModel`。

### 2.4 配置（config/config.yaml 模型段）
```yaml
model:
  mode: api
  timeout: 120               # 全局默认，工厂合并进所选子段
  max_retries: 2
  api:
    model_type: openai_chat
    model_name: gpt-4o
    api_key: ${OPENAI_API_KEY}
    base_url: https://api.openai.com/v1
    temperature: 0.3
    stream: false
  local:
    model_type: openai_chat
    model_name: qwen3-8b-finr1
    api_key: EMPTY
    base_url: http://localhost:8000/v1
    temperature: 0.3
    stream: false
```
> 密钥用 `${ENV_VAR}`；提交 `config.example.yaml` 脱敏模板。

### 2.5 generate() 实现策略（已决策）
- 本期 `generate()` **直连 OpenAI 兼容端点**（`api` 用真实 key，`local` 指向 vLLM `/v1`），不依赖 AgentScope runtime。
- `build_agentscope_config()` 仅作为给后续 `services/` AgentScope 编排的"配置导出"，不影响 `generate()` 行为。
- 依赖新增：`openai`（直连）；`agentscope` 留待服务层（编码前 `pip show` 核实版本，并锁定 `openai_chat` 字段名）。
