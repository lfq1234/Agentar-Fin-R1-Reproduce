## 1. 目标与非目标

**目标**
- 用 **AgentScope** 构建金融推理 **multi-agent**：1 个协调者(Coordinator) + 5 个领域专家(Banking / Securities / Insurance / Trust / MutualFunds)。
- 模型层 **同时支持 API 与本地两种模式**，调用方式在 `model/api/` 与 `model/local/` 中彻底分离，互不耦合。
- 用 **FastAPI** 暴露 `/v1/chat` 与 `/v1/analyze` 供前端调用。
- 所有配置集中在 `config/`（YAML），通过 `model.mode` 切换 API / 本地。

**非目标（本期不做）**
- 不接持久化数据库（仅在 `db/` 留脚手架，`db.enabled=false`，会话历史用内存）。
- 不做鉴权/多租户。
- 不内嵌训练；本地模式仅消费 training 产出的检查点（经 vLLM 暴露）。

## 2. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| Web 框架 | FastAPI + Uvicorn | 异步，`routes/` 定义接口 |
| Agent 框架 | AgentScope（v1，异步优先） | `services/` 内编排多智能体 |
| 模型（API） | `model/api/` → `openai_chat` wrapper | gpt-4o / DeepSeek / 任意 OpenAI 兼容 |
| 模型（本地） | `model/local/` → vLLM OpenAI 兼容端点 | 复用同一 wrapper，仅 `base_url` 不同 |
| 配置 | YAML + PyYAML | 集中在 `config/` |
| 校验 | pydantic v2 | 请求/响应 schema |
| 数据层 | SQLAlchemy（脚手架） | `db/`，本期不启用 |
| 测试 | pytest + httpx TestClient | 含模型连通 smoke test |

## 4. 配置设计（YAML，集中管理）

### 4.1 原则
- 所有配置集中在 `app/config/config.yaml`，**一处管理**。
- 密钥类字段用 `${ENV_VAR}` 引用环境变量，避免明文入库；提交 `config.example.yaml` 作脱敏模板。
- 通过 `model.mode: api | local` 切换模型调用方式，无需改代码。

### 4.2 `app/config/config.yaml`（完整示例）
```yaml
# ============================================================
# Agentar-Fin-R1-Reproduce 后端总配置（集中管理）
# 密钥用 ${ENV_VAR} 引用；部署前复制为 config.local.yaml 并按环境覆盖。
# ============================================================

server:
  host: 0.0.0.0
  port: 8000
  reload: false
  log_level: INFO
  cors:
    allow_origins: ["*"]
    allow_methods: ["*"]
    allow_headers: ["*"]

# 模型接口层：mode 决定走 model/api 还是 model/local
model:
  mode: api                  # api | local
  timeout: 120
  max_retries: 2
  api:                       # —— API 模式（model/api/ 使用）
    model_type: openai_chat
    model_name: gpt-4o
    api_key: ${OPENAI_API_KEY}
    base_url: https://api.openai.com/v1
    temperature: 0.3
    stream: false
  local:                     # —— 本地模式（model/local/ 使用，vLLM）

    model_name: qwen3-8b-finr1

  enabled: false
  type: sqlite               # sqlite | postgres
  path: ./data/app.db

# 智能体配置（services/agent_runtime.py 使用）
agents:
  coordinator:
    name: Coordinator
    sys_prompt_file: agent/prompts/coordinator.txt
  experts:
    - scene: Banking
      name: BankingExpert
      sys_prompt_file: agent/prompts/banking.txt
    - scene: Securities
      name: SecuritiesExpert
      sys_prompt_file: agent/prompts/securities.txt
    - scene: Insurance
      name: InsuranceExpert
      sys_prompt_file: agent/prompts/insurance.txt
    - scene: Trust
      name: TrustExpert
      sys_prompt_file: agent/prompts/trust.txt
    - scene: MutualFunds
      name: MutualFundsExpert
```

### 4.3 配置加载（`app/config/__init__.py`）
```python
import os
import yaml
from pydantic import BaseModel
from pathlib import Path

class Settings(BaseModel):
    server: dict
    model: dict
    db: dict
    agents: dict

def _sub_env(raw: str) -> str:
    # 将 "${OPENAI_API_KEY}" 替换为环境变量
    if isinstance(raw, str) and raw.startswith("${") and raw.endswith("}"):
        return os.environ.get(raw[2:-1], "")
    return raw

def load_config(path: str | None = None) -> Settings:
    path = path or os.environ.get("CONFIG_PATH", "app/config/config.yaml")
    raw = yaml.safe_load(Path(path).read_text(encoding="utf-8"))
    # 递归替换 ${ENV}
    def walk(node):
        if isinstance(node, dict):
            return {k: walk(v) for k, v in node.items()}
        if isinstance(node, list):
            return [walk(v) for v in node]
        return _sub_env(node)
    return Settings(**walk(raw))

config = load_config()
```
> `model.mode` 取值决定 `model/factory.py` 实例化 `api` 还是 `local` 实现。

## 5. 模型接口层（`model/`）

两种调用方式物理分离，便于维护与测试，互不影响。

```
model/
├── base.py        # ModelInterface(abc)：generate(prompt, **kw)->str；astream(...)
├── factory.py     # get_model(cfg) -> 按 cfg.model.mode 返回 ApiModel / LocalModel
├── api/
│   └── openai_api.py   # ApiModel：云端 openai_chat（base_url=云端）
└── local/
    └── vllm_local.py   # LocalModel：本地 vLLM OpenAI 兼容（base_url=本地端点）
```

### 5.1 抽象接口 `model/base.py`
```python
from abc import ABC, abstractmethod

class ModelInterface(ABC):
    @abstractmethod
    def build_agentscope_config(self) -> dict:
        """返回 AgentScope openai_chat 模型配置字典。"""
    @abstractmethod
    def generate(self, prompt: str, **kwargs) -> str: ...
```

### 5.2 `model/api/openai_api.py`（API 模式）
- 读取 `config.model.api`（`base_url`=云端、`api_key`=真实 KEY）。
- `build_agentscope_config()` 返回云端 `openai_chat` 配置。

### 5.3 `model/local/vllm_local.py`（本地模式）
- 读取 `config.model.local`（`base_url`=vLLM 本地端点、`api_key`=占位）。
- 复用同一 `openai_chat` wrapper，仅端点不同——**调用方式分离，但底层统一**。

### 5.4 工厂 `model/factory.py`
```python
from app.config import config
from app.model.api.openai_api import ApiModel
from app.model.local.vllm_local import LocalModel

def get_model():
    section = config.model["local"] if config.model["mode"] == "local" else config.model["api"]
    cls = LocalModel if config.model["mode"] == "local" else ApiModel
    return cls(section)
```
> 注：AgentScope v1 的 Model/Agent 具体类名以安装版本 tutorial 为准，编码前核实（`pip show agentscope`）。

```

├── inference.py      # run_agent(message, scene, task, structured) -> 对外服务入口
└── agent_runtime.py  # 构建 Coordinator+专家、msghub 编排、汇总
```

### 7.1 多 Agent 拓扑
```
用户消息 ─▶ Coordinator(路由/意图) ─▶ 按 scene 分发 ─▶ 领域专家(1~N) ─▶ 汇总答案
```
- **Coordinator**：`scene` 已指定则直送对应专家；否则做意图识别判定场景。
- **5 领域专家**：各持 `agent/prompts/*.txt` 中的领域 system prompt，共享 `get_model()` 产出的模型配置。

### 7.2 `agent_runtime.py`（编排，异步）
```python
import agentscope
from agentscope.msghub import msghub
# agentscope.init(model_configs=[model.build_agentscope_config()])
# 用 msghub([coordinator, *experts, user]) 建立会话并控制发言顺序
```
- AgentScope v1 异步优先，`run()` 一律 `async`，由 `routes/` `await`。

### 7.3 `inference.py`
- 对外暴露 `run_agent(...)`：组装请求 → 调 `agent_runtime` → 返回 `reply` 或结构化 `AnalyzeResponse`。

```python
class ChatRequest(BaseModel):
    message: str
    scene: str | None = None     # Banking/Securities/Insurance/Trust/MutualFunds
    task: str | None = None

class ChatResponse(BaseModel):
    reply: str

    scene: str | None = None

class AnalyzeResponse(BaseModel):
    intent: str | None = None
    slots: dict[str, str] = {}
    tool_plan: list[str] = []
    expression: str = ""
```

## 9. 文档组织（`docs/`）

`docs/` 采用**「两位数字编号 + 描述」作为文件夹**的扁平结构：每个编号项都是一个文件夹，文件夹内再放需求文档与技术文档。

```
docs/
├── 00-总文档/              # 总架构（编号 00，描述“总文档”）
│   └── 00-总文档.md        #   本文件
├── 01-模板/                # 模板（编号 01，描述“模板”）
│   ├── 需求文档.md         #   需求原文模板
│   └── 技术文档.md         #   技术设计模板
├── 02-<需求短名>/          # 第一次真实需求（编号顺延 +1）
│   ├── 需求文档.md
│   └── 技术文档.md
└── 03-<需求短名>/          # 后续需求继续顺延
    ├── 需求文档.md
    └── 技术文档.md
```

- **命名规则**：文件夹名 = `<两位数字>-<短名>`，数字仅用于排序，不进入文件名。
- **`00` 固定为总文档**；之后的数字分配给“每次需求”，新增需求顺延当前最大编号 +1，已分配的编号不再复用。
- **每个编号文件夹内**同时放 `需求文档.md` 与 `技术文档.md`（即“建个文件夹，统一放需求和技术文档”）。
- 编号递增由本总文档 §12 / 各文件夹内文档头部统一登记。

## 13. 风险与待定项

- **工具调用（tool_plan 落地）**：真实金融工具注册表（行情/计算/合规）留后续版本。
