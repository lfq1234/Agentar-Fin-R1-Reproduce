# 联调报告 —— 前后端联调（模块 10）

> 版本：v1.1 ｜ 日期：2026-08-07
> 范围：真实浏览器前端（Vite :5173）↔ 真实后端 API（uvicorn :8000）的链路联调。
> 与 `需求文档.md` / `技术文档.md` 配套：本文只记录**实际跑通结果**，不重复设计。

## 1. 概述

本次联调目标：在不触发 AI 模型推理的前提下，验证前端与后端之间的**路由可达性、鉴权链路、契约一致性**。

- ✅ 覆盖：健康检查、注册、登录、鉴权拦截、个人文档列表、知识图谱、历史会话、经 Vite 代理的全链路。
- ⏸️ 不覆盖（按约定）：`/api/v1/chat` 与 `/api/v1/analyze`。二者会触发本地模型加载（Qwen3-0.6B，位于 `D:/models`），首次调用 >60s 且单 worker 同步推理会阻塞事件循环，属于「模型部署」层面的事，不在本次联调范围。

环境现状（联调时两服务均在运行）：

| 服务 | 地址 | 启动方式 |
|------|------|----------|
| 后端 | `http://localhost:8000` | `uvicorn app.main:app --port 8000`（anaconda base python，需 `AUTH_SECRET_KEY` 环境变量） |
| 前端 | `http://localhost:5173` | `npm run dev`（Vite，代理 `/api` → `http://localhost:8000`） |

> ⚠️ Vite 绑定的是 `localhost`（IPv6 `::1`），浏览器必须用 **`http://localhost:5173`**，用 `127.0.0.1:5173` 连不上。

## 3. 发现的问题与风险（Findings）

| 编号 | 级别 | 现象 | 说明 / 建议 |
|------|------|------|------------|
| **F1** | P3 | 错误/失效 token 返回 **403** 而非 401 | FastAPI 默认 `HTTPBearer` 对缺失/非法 token 抛 403。功能无碍，若前端按 401 做跳转需对齐。 |
| **F2** | P2 | 文档上传返回 200 但 `status:"error"` | 08 的 ingest 流水线在**嵌入环节**调用本地嵌入服务 `http://localhost:9000/v1`（未启动）导致失败。端点**优雅降级**（不崩溃、不 5xx）。**v1.1 更新：PDF 解析已支持**——`parser.py` 用 `pypdf` 抽每页文本，依赖已写入 `pyproject.toml`；现 PDF 能过解析关，剩余阻塞纯粹是嵌入服务未起。上线前需先起嵌入服务。 |
| **F3** | P2 | `/api/v1/analyze` 无 `CurrentUser` 鉴权 | `chat.py` 的 `analyze_endpoint` 仅挂 `SessionDep`，而 `chat` 端点挂了 `CurrentUser`。两者鉴权不对称，建议统一。 |
| **F4** | P3 | 密码策略最低 8 位 | 注册接口 Pydantic schema `min_length=8`，`123456` 会被 422 拒绝；初始账号已用 `admin / 12345678` 创建。 |
| **F5** | P3 | Vite 绑 `localhost` 非 `127.0.0.1` | 联调用 `http://localhost:5173`，不要用 `127.0.0.1`。 |

## 4. 启动与账号速查

```bash
# 后端（anaconda base python）
cd backend
export AUTH_SECRET_KEY="<任意非空字符串>"      # config.yaml 经 ${AUTH_SECRET_KEY} 注入，缺失会启动失败
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# 前端（受管 node 22）
cd frontend
npm run dev                                    # 监听 http://localhost:5173，代理 /api -> :8000
```

## 5. 结论

- ✅ **前后端核心链路联通**：健康检查、注册、登录、鉴权、个人文档、知识图谱、历史会话在直连与 Vite 代理两种方式下均正常。
- ✅ **契约一致**：08 响应字段为 camelCase（`uploadedAt` 等），与前端 `types/agent.ts` 对齐；响应结构（`DocumentListOut` 等）可解析。
- ✅ **前端可编译**：`vite build` 零错误，依赖（含 AntV G6）完整。
- ⏸️ **AI 推理（chat/analyze）未联调**：需本地模型 + 嵌入服务就绪后再单独验证（详见 F2/F3 与训练侧 A800 适配说明）。
- ⚠️ **待办**：补齐嵌入服务（:9000）（PDF 解析已完成，见 F2）、统一 analyze 鉴权（F3）、对齐 token 错误码（F1）。
