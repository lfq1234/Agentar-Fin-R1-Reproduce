## 1. 总览

本模块是 `Agentar-Fin-R1-Reproduce` 的**前后端联调层**：把真实浏览器中运行的前端（React + Vite + TS）与真实运行的后端（FastAPI）对接，端到端验证「前端消费后端」的闭环，并产出**契约一致性清单**（需求文档 §7 的 D1~D6）。

与 `05-后端联调` 的边界：**05 用 `TestClient`/curl 在后端进程内自测，不打开浏览器、不跑任何前端代码**；10 必须打开浏览器跑真实前端，验证 Vite 代理、CORS、JWT 令牌流程、错误 UX、UI 渲染与契约对齐。

```
┌──────────────────────────────────────────────────────────────────┐
│  浏览器（真实前端，:5173）                                          │
│  React + Vite + TS                                                │
│  ├─ LoginPage        → 注册/登录（09），令牌存 localStorage        │
│  ├─ useChat          → POST /api/v1/chat、/api/v1/analyze          │
│  ├─ client.ts        → fetch 封装 + Bearer + 401/403 跳登录        │
│  ├─ PersonalDocsPanel→ POST /api/v1/documents、/knowledge-graph    │
│  └─ types/agent.ts   → 后端契约镜像（待对齐 D1~D6）                │
└───────────────┬──────────────────────────────────────────────────┘
                │  同源 :5173，请求 /api/*（dev 无跨域）
                │  Vite proxy: "/api" → http://localhost:8000
                ▼
┌──────────────────────────────────────────────────────────────────┐
│  后端（FastAPI，:8000）                                            │
│  app/main.py（prefix="/api" + CORS 中间件）                        │
│  ├─ /api/health                     公开                           │
│  ├─ /api/v1/chat        (CurrentUser)→ chat_service → 02 run()    │
│  ├─ /api/v1/analyze      (公开，无鉴权)→ analyze_service           │
│  ├─ /api/v1/auth/*       register/login/me（09）                  │
│  ├─ /api/v1/documents    (CurrentUser)→ 08 个人文档               │
│  ├─ /api/v1/knowledge-graph (CurrentUser)                         │
│  ├─ /api/v1/rag/retrieve (CurrentUser)                           │
│  └─ /api/v1/history/*    (CurrentUser)→ 07 会话历史（前端未消费） │
└──────────────────────────────────────────────────────────────────┘
```

**关键事实（已核对源码）**
- 路径一致：后端 `main.py` 所有路由 `include_router(prefix="/api")`；前端 `client.ts` 的 `BASE="/api/v1"`，`health()` 直打 `/api/health` —— **前后端路径已对齐**，dev 期经 Vite 代理同源无跨域。
- 鉴权已接通：后端 `chat.py`/`documents.py`/`history.py` 均 `CurrentUser`；前端 `authHeaders()` 自动加 `Bearer`，`login()` 走 OAuth2 表单流（与 `auth.py` 一致）。
- 令牌失败处理已接通：前端 `request()` 遇 401/403 调 `clearToken()` + 派发 `UNAUTHORIZED_EVENT`，`App` 监听后切回 `LoginPage`。
- **契约错位已存在**（D1~D6）：后端 `ChatResponse.agent_trace`、`ChatRequest.use_personal_docs` 前端未镜像；07 历史 API 前端未调用。详见需求文档 §7。

## 3. 环境 / 配置（联调准备）

### 3.1 后端启动
```bash
cd backend
# venv 含 fastapi/sqlmodel/aiosqlite/agentscope；security.secret_key 必填
uvicorn app.main:app --reload --port 8000
# lifespan 调 init_db() + migrate_user_columns() + init_history_db() + install_history_tracing()
```
- 验收：`curl http://localhost:8000/api/health` → `{"status":"ok"}`。

### 3.2 前端启动
```bash
cd frontend
pnpm install   # 或 npm install
pnpm dev       # Vite :5173，proxy /api → :8000
```
- 浏览器开 `http://localhost:5173`；前端所有 `/api/*` 经代理同源打到后端。

### 3.3 配置要点
- **dev 无跨域**：因 Vite 代理，浏览器与后端同源（:5173 代理到 :8000），CORS 中间件虽加载但不触发预检。
- **生产跨域（D5）**：直连时需 `config.yaml` 的 `server.cors.origins` 显式填前端域名（默认 `["*"]` 仅开发可用）。
- **Mock 开关**：`.env` `VITE_USE_MOCK=true` 时文档/图谱走 `mock/personalDocs.ts`；chat/auth/health 仍打真实后端（mock 不覆盖主链路与鉴权）。

## 4. 联调手段

| 手段 | 用途 | 说明 |
| --- | --- | --- |
| 浏览器手动验证 | 主手段 | 打开 `:5173`，真实走注册/登录/聊天/文档全流程；观察 UI 与 Network。 |
| 浏览器 DevTools Network | 抓包核对 | 核对请求路径、`Authorization` 头、响应字段、401/403 跳登录。 |
| `curl` 直连后端 | 隔离后端 | 不经过代理，验证 CORS 头（`-H "Origin: ..." -i`）、令牌校验。 |
| Playwright / Cypress | 固化 E2E（可选） | 把「登录→聊天→文档」固化为可回归脚本（见 §7）。 |
| 契约比对脚本 | 一致性核验 | 读前端 `types/agent.ts` 与后端 pydantic 模型，diff 字段（见 §6）。 |

> 与 05 区别：10 **必须**打开浏览器；`TestClient` 仅用于后端自测，不替代 10 的浏览器验证。

## 5. 联调执行手册（覆盖需求 §3 全部目标）

### 5.1 环境拉起（目标 1）
1. 起后端 `uvicorn :8000`；起前端 `pnpm dev :5173`。
2. 浏览器开 `:5173` → 观察 Header 状态点：`health()` 成功变 `ok`，失败变 `down`。
3. DevTools Network 确认 `/api/health` 经代理 200。

### 5.2 鉴权闭环（目标 2，09）
1. 未登录直接打 `POST /api/v1/chat` → 预期 **401**，`App` 切回 `LoginPage`。
2. 注册：`POST /api/v1/auth/register` `{username, password}` → 201。
3. 登录：`POST /api/v1/auth/login/access-token`（表单 `username`/`password`）→ 取 `access_token`，前端 `setToken` 存 `localStorage`，自动 `me()` 进入聊天页。
4. 刷新页面 → 仍登录（令牌未过期）。
5. 用失效/停用令牌打受保护接口 → **403** → 跳登录。

### 5.3 聊天主链路（目标 3，02/03）
1. 发一条消息（带 `scene` 或不带）→ `POST /api/v1/chat`。
2. 断言 `reply` 非空；`compliance_notes`/`risk_flags` 渲染到气泡；`conversation_id` 回填 `ChatSession.conversationId`。
3. 观察响应是否含 `agent_trace`（后端已返回，前端当前未消费 → **D1**）。

### 5.4 续聊一致性（目标 4）
1. 首条消息不带 `conversation_id` → 记录返回的 `conversation_id`。
2. 同会话再发 → 带该 `conversation_id`。
3. 断言 `conversation_id` 一致；后端 `messages` 表记录数增长。

### 5.5 结构化分析（目标 5）
1. 对最近助手回复 `POST /api/v1/analyze` → `AnalyzePanel` 展示 `intent`/`slots`/`tool_plan`/`expression`。

### 5.6 个人文档闭环（目标 6，08）
1. `PersonalDocsPanel` 上传文件 → `POST /api/v1/documents`（multipart `files`）。
2. 列表/状态/删除/图谱/RAG 依次验证；断言 RAG 仅命中当前用户文档（D2：若开个人文档召回需 `use_personal_docs`，前端未接 → 暂只能验默认作用域）。

### 5.7 数据隔离（目标 7，09）
1. 账号 A 登录 → 建会话/传文档 → 记 `conversation_id`/`doc_id`。
2. 退出 → 账号 B 登录 → 打同一 `conversation_id`/`doc_id` → 预期 **403/404**。

### 5.8 错误 UX（目标 8）
1. 后端未起 → 前端 `ApiError(status=0)` 文案（网络错误）。
2. 模型不可用 → 后端 500 `model_invoke_failed` → 前端文案不崩溃。

## 6. 契约一致性校验（核心交付，对齐需求 §7）

逐字段比对前端 `types/agent.ts` 与后端模型，diff 结果即需求文档 §7 的 D1~D6。可直接用脚本辅助（读两个文件提取 interface/pydantic 字段名），但**人工核对 + 登记**为本模块交付物。

| 编号 | 契约点 | 后端真实 | 前端镜像 | 处置 |
| --- | --- | --- | --- | --- |
| D1 | `ChatResponse.agent_trace` | `List[Dict[str,Any]]`（c430051） | 缺失 | 前端 `ChatResponse` 补字段；可选渲染专家步骤 |
| D2 | `ChatRequest.use_personal_docs` | `bool=false` | 缺失 | `ChatRequest` 补字段；`PersonalDocsPanel` 开关经 `send` 发送 |
| D3 | 会话历史 API | `/api/v1/history/*`（07）已实现 | `client.ts` 未调用 | 接 history 接口做会话列表 + 回放 |
| D4 | 文档上传字段名 | `documents.py:46` `files: list[UploadFile] = File(...)`（已核对一致） | `form.append("files", f)` | 已对齐，无 422 风险 |
| D5 | 生产 CORS | `server.cors.origins` 默认 `["*"]` | — | 生产显式填前端域名 |
| D6 | `ChatRequest.user_id` | 接受但忽略 | 不发送 | 后端清理冗余字段 |

> 本模块**只登记不修复**。修复 D1~D6 属前端/后端改动，另立任务（建议优先级见需求文档 §7）。

## 7. 测试策略

- **手动浏览器验证（主）**：覆盖需求 §3 全部 9 项目标；本模块交付以「清单打勾 + 截图/录屏」为准。
- **契约比对（文档化）**：需求 §7 / 技术 §6 的 D1~D6 清单即一致性测试产物。
- **可选固化（不属本模块强制）**：若要把联调固化为回归，可在 `frontend/` 引入 Playwright，脚本覆盖「注册→登录→聊天→上传文档」；或在 `backend/tests/` 加 `test_frontend_contract.py`（解析前端 `types/agent.ts` 与后端模型字段做断言）。**本文档仅给出方案，落地另立任务。**
