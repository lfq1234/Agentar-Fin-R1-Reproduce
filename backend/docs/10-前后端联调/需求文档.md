> 版本：v0.1（草案，仅产出需求/技术文档，未实际起前后端服务联调）

> 关联：
> - `05-后端联调`（后端进程内端到端，`TestClient`/curl 驱动，**不涉及任何浏览器/UI 代码**）

## 1. 背景与目标

前端（`/frontend`，React + Vite + TypeScript）与后端（`/backend`，FastAPI）**已分别存在且各自可独立验证**：

- **前端**已落地完整 UI：`LoginPage`（09 登录/注册门禁）、`useChat`（会话状态机）、`client.ts`（统一 `fetch` 封装 + 令牌管理）、`types/agent.ts`（后端契约镜像）、`PersonalDocsPanel`/`KnowledgeGraphViewer`/`SessionList` 等组件。
- **后端**已落地全部 API：`/api/v1/chat`、`/api/v1/analyze`、`/api/health`、`/api/v1/auth/*`（09）、`/api/v1/documents`、`/api/v1/knowledge-graph`、`/api/v1/rag/retrieve`（08）、`/api/v1/history/*`（07）。

但二者**从未在浏览器里真正对接过**——`05-后端联调`只验证了后端进程内链路（用 `TestClient` 打 API，不发任何前端请求）。因此存在「各自单测都绿、拼起来不一定通」的风险：契约字段对不齐、dev 代理/CORS 没验证、鉴权令牌流程未走过真实浏览器、错误 UX 未联调。

**本模块（10-前后端联调）的目标**：把「真实浏览器中的前端」与「真实运行的后端」接起来，端到端验证以下闭环，并**产出一份前后端契约一致性清单**（发现并登记字段错位，供后续修复）：

1. 开发环境一键拉起前后端，浏览器经 Vite 代理打到后端 `/api`；
2. 鉴权闭环：注册 → 登录（拿 Bearer 令牌存 `localStorage`）→ `me` → 无令牌 401 / 失效 403 跳登录；
3. 聊天主链路：发消息 → 后端 `run()` 多智能体 → 回显 `reply` + 合规/风控；
4. 续聊一致性：带 `conversation_id` 复用后端会话；
5. 结构化分析：`/api/v1/analyze` 四字段回显；
6. 个人文档闭环：上传（multipart）→ 列表/状态 → 图谱 → 个人文档 RAG 召回；
7. 数据隔离：A 账号的会话/文档对 B 账号不可见（令牌作用域）；
8. 错误 UX：401/403 跳登录、网络故障 `status=0` 文案、模型不可用降级提示；
9. 契约一致性：逐字段核对前端 `types/agent.ts` 与后端 pydantic 模型，登记错位（见 §7）。

> 与 05 的边界：**05 不打开浏览器、不跑前端代码**；10 必须打开浏览器、跑真实前端、验证真实代理/CORS/令牌/UI 行为。05 是「后端自测」，10 是「前端消费后端」。

## 2. 范围

### 2.1 包含（In Scope）
- **开发环境拉起**：`uvicorn` 后端 + `vite` 前端，验证 `/api` 代理可达、`/api/health` 探活（驱动 Header 状态点）。
- **鉴权联调（09）**：注册 / 登录（OAuth2 表单流）/ `me` / 令牌持久化 / 401·403 跳登录。
- **聊天联调（02/03）**：`POST /api/v1/chat` 主链路、`conversation_id` 续聊、`compliance_notes`/`risk_flags` 渲染。
- **分析联调（02）**：`POST /api/v1/analyze` 结构化四字段。
- **文档联调（08）**：上传 / 列表 / 状态 / 删除 / 知识图谱 / RAG 检索，鉴权作用域验证。
- **契约一致性核对**：前端 `types/agent.ts` ↔ 后端 `app/db/models/*`、`app/routes/*` 响应模型，逐字段比对，登记错位（D1~D6，见 §7）。
- **错误 UX 联调**：401/403 跳登录、网络错误、模型降级。
- **数据隔离联调（09）**：双账号会话/文档互不可见。

- 后端内部链路重测（属 05，10 仅消费不重做）。
- 模型训练、Agent 编排、RAG 检索实现本身（属 01/02/04/08）。
- 前端组件重构、视觉改版（10 只验证「能否接通」，不改进样式）。
- 自动化 E2E（Playwright）落地为代码——本文档给出方案与清单，但**实施以文档 + 手动浏览器验证为主**；如需固化进 CI 见技术文档 §7。
- 流式（SSE）响应（本期后端为同步 JSON）。

## 3. 联调目标（功能需求）

### 目标 1 · 环境拉起与代理联调
- `cd backend && uvicorn app.main:app --port 8000`；`cd frontend && npm run dev`（Vite :5173）。
- 浏览器打开 `http://localhost:5173`，前端 `fetch("/api/...)` 经 Vite `proxy: {"/api": "http://localhost:8000"}` 打到后端。
- 断言：`GET /api/health` 经代理返回 `200 {"status":"ok"}`；Header 状态点变 `ok`；后端 CORS 中间件加载正常（`main.py` `_cors_settings`）。

### 目标 2 · 鉴权闭环联调（09）
- **注册**：`POST /api/v1/auth/register` `{username, password, email?}` → 201 `UserPublic`。
- **登录**：`POST /api/v1/auth/login/access-token`（表单 `username`/`password`）→ `{access_token, token_type: "bearer"}`；前端 `setToken` 存 `localStorage["agentar_token"]`，随后自动 `me()` 拉当前用户并进入聊天页。
- **当前用户**：`GET /api/v1/auth/me`（带 `Authorization: Bearer <token>`）→ `UserPublic`。
- **无令牌**：未登录直接打 `/api/v1/chat` → 401；前端 `clearToken` + 派发 `UNAUTHORIZED_EVENT` → `App` 监听切回 `LoginPage`。
- **失效/停用**：令牌过期或账号 `is_active=false` → 403 → 同跳登录。
- 断言：令牌写入 `localStorage`；刷新页面仍保持登录（令牌未过期）；401/403 必跳登录。

### 目标 3 · 聊天主链路联调（02/03）
- `POST /api/v1/chat` 请求体 `{message, conversation_id?}`（**前端不传 `user_id`，也不传 `scene`**——由后端多智能体框架决定谁来回答，见下方「智能体/场景选择」说明）。
- 响应 `{reply, conversation_id?, compliance_notes[], risk_flags[], agent_trace[]}`。
- `useChat.send` 把 `res.reply` 入 `UiMessage`，`compliance_notes`→`compliance`、`risk_flags`→`risk` 渲染到气泡。
- 断言：`reply` 非空；合规/风控数组渲染；`conversation_id` 回填 `ChatSession.conversationId`。

> **智能体/场景选择（已变更）**：前端**不再提供场景/智能体下拉选择**（`SceneSelect` 组件已删除，`ChatRequest.scene` 不再由前端发送）。后端 `run()`（`system.py:184`）在 `scene is None` 时经 Coordinator 自动路由到领域专家；跨域问题再经 `ExpertBoard` 互询/圆桌。这是 02 多智能体通讯的既定设计——「由后端智能体聊天决定谁来回答」。因此契约核对中不再有「前端 scene 下拉 vs 后端 scene 枚举」这一错位项（原 D 清单中的隐含 scene 一致性已随选择器移除而消解）。

### 目标 4 · 续聊一致性联调
- 首次发消息不带 `conversation_id` → 后端新建会话返回 `conversation_id`；前端存到 `ChatSession`。
- 同一会话再次发消息带该 `conversation_id` → 后端按同一会话追加（`conversations` 表同 `conversation_id`，`user_id` 来自令牌）。
- 断言：续聊 `conversation_id` 一致；后端 `messages` 表记录随对话增长。

### 目标 5 · 结构化分析联调（02）
- 针对最近一条助手回复，`POST /api/v1/analyze` `{message}` → `{intent?, slots{}, tool_plan[], expression}`（前端不再传 `scene`）。
- 断言：`AnalyzePanel` 能展示 `intent`/`slots`/`tool_plan`/`expression`，类型与契约一致。

### 目标 6 · 个人文档闭环联调（08）
- **上传**：`POST /api/v1/documents`（multipart `files`）→ `{documents: PersonalDocument[]}`；`PersonalDocsPanel` 显示解析状态。
- **列表/状态**：`GET /api/v1/documents`、`GET /api/v1/documents/{id}/status`。
- **删除**：`DELETE /api/v1/documents/{id}` → 204。
- **图谱**：`GET /api/v1/knowledge-graph` → `{nodes, edges}` → `KnowledgeGraphViewer` 渲染。
- **RAG 召回**：`POST /api/v1/rag/retrieve` → 命中个人文档片段（08 作用域按 `user_id` 过滤）。
- 断言：上传后能在列表/图谱看到；RAG 检索只命中**当前用户**文档。

### 目标 7 · 数据隔离联调（09）
- 账号 A 登录 → 创建会话、上传文档 → 记录 `conversation_id`/`doc_id`。
- 退出 → 账号 B 登录（或无令牌）→ 打同一 `conversation_id`/`doc_id` → 应 403/404（作用域隔离）。
- 断言：B 看不到 A 的会话与文档；`me` 返回 B 自身。

### 目标 8 · 错误 UX 联调
- 401/403 → 跳登录（`UNAUTHORIZED_EVENT` 流程）。
- 网络不可达（后端未起）→ `fetch` 抛异常 → `ApiError(status=0, "网络错误…")` → `ErrorBanner` 文案。
- 模型不可用 → 后端 `ModelInvokeError` → 500 `{error:"model_invoke_failed"}` → 前端 `ApiError` 文案（不崩溃）。

### 目标 9 · 契约一致性核对（核心交付）
- 逐字段比对前端 `types/agent.ts` 与后端模型，产出 §7 的错位清单，作为后续修复依据。

## 4. 联调契约（对齐后端真实接口，已核对源码）

> 10 不新定义契约，仅消费已锁定接口；以下字段均经 `backend/app/routes/*`、`app/db/models/*` 核对。

### 4.1 统一路径与代理
- 后端：`main.py` 以 `prefix="/api"` 挂载 → 实际路径 `/api/health`、`/api/v1/chat`、`/api/v1/auth/*`、`/api/v1/documents`、`/api/v1/knowledge-graph`、`/api/v1/rag/retrieve`、`/api/v1/history/*`。
- 前端：`client.ts` 常量 `BASE = "/api/v1"`（chat/analyze/auth/documents 走此），`health()` 直接打 `/api/health`。
- Dev 代理：`vite.config.ts` `server.proxy["/api"] = "http://localhost:8000"`；浏览器同源（:5173）无跨域。

### 4.2 鉴权（09，已核对 `auth.py`）
| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| POST | `/api/v1/auth/register` | `UserCreate{username, password, email?}` JSON | 201 `UserPublic{id,username,email}` |
| POST | `/api/v1/auth/login/access-token` | **表单** `username`/`password`（`application/x-www-form-urlencoded`） | `{access_token, token_type:"bearer"}` |
| GET | `/api/v1/auth/me` | `Authorization: Bearer <token>` | `UserPublic` |

- 令牌：`Authorization: Bearer <token>`；过期分钟取 `config.security.access_token_expire_minutes`（默认 60）。
- 强制鉴权端点：`chat`、`documents`、`knowledge-graph`、`rag/retrieve`、`history/*` 均 `CurrentUser` 依赖；缺令牌 401、失效/停用 403。

### 4.3 聊天 / 分析（02/03，已核对 `chat.py` + `conversation.py`）
- `ChatRequest{message:str, user_id?:int(已弃用，服务端忽略), conversation_id?:int, use_personal_docs:bool=false}`。
- `ChatResponse{conversation_id?:int, reply:str, compliance_notes:str[], risk_flags:str[], agent_trace:list[dict]}`（**前端不再发送 `scene`**，后端自动路由）。
- `AnalyzeRequest{message:str}`；`AnalyzeResponse{intent?, slots:dict, tool_plan:str[], expression:str}`。
- 场景枚举（后端 `SCENES`）：`Banking`/`Securities`/`Insurance`/`Trust`/`MutualFunds`；由后端 Coordinator 路由决定，**前端不暴露选择 UI**。

### 4.4 文档 / 图谱 / RAG（08，已核对 `documents.py`）
- `POST /api/v1/documents`（multipart `files: List[UploadFile]`）→ `{documents: PersonalDocument[]}`。
- `GET /api/v1/documents` → 同；`GET /api/v1/documents/{doc_id}/status` → `PersonalDocument`；`DELETE /api/v1/documents/{doc_id}` → 204。
- `GET /api/v1/knowledge-graph` → `{nodes, edges}`。
- `POST /api/v1/rag/retrieve` → RAG 命中（按 `user_id` 过滤）。
- `PersonalDocument{id, filename, size, status, error?, uploadedAt, summary?}`；`status ∈ pending|parsing|done|error`。

### 4.5 会话历史（07，已核对 `history.py`，前端尚未消费）
- `GET /api/v1/history/sessions` → `SessionMeta[]`；`GET /api/v1/history/sessions/{conversation_id}` → `SessionDetail`；`GET /api/v1/history/search` → `SearchHit[]`；`GET /api/v1/history/sessions/{conversation_id}/export` → 导出。
- **当前前端 `client.ts` 未调用以上任一接口**（会话仅内存态，`ChatSession` 刷新即丢）——列为 §7 D3 缺口。

## 5. 配置（联调环境）

- **后端**：`config/config.yaml` 设 `db.enabled:true`、`db.type:sqlite`；`security.secret_key` 必填（缺失即启动失败）；`server.cors.origins`（生产需显式填前端域名，开发因代理无需）。
- **前端**：`.env`（Vite）`VITE_USE_MOCK=false`（默认）走真实后端；`VITE_USE_MOCK=true` 时文档/图谱走内置 mock（`mock/personalDocs.ts`），**但 chat/auth/health 仍打真实后端**（mock 开关不覆盖鉴权与主链路）。
- **代理**：`vite.config.ts` `server.proxy["/api"]` → `http://localhost:8000`（开发期）。
- **模型（01）**：`model.mode`/`emb.mode` api 或 local；联调真实聊天需可用模型。

## 7. 已知问题 / 待办（联调发现的契约错位，核心交付）

> 以下为「前后端从未对接」导致的真实错位，经核对前端 `types/agent.ts` 与后端模型得出，供后续修复排期。

| 编号 | 契约点 | 后端（真实） | 前端（types/agent.ts） | 影响 | 建议优先级 |
| --- | --- | --- | --- | --- | --- |
| **D1** | `ChatResponse.agent_trace` | `List[Dict[str,Any]]`（c430051 新增，07 落库） | `ChatResponse` 无此字段 | 专家多智能体对话已落库(07)，但前端不可见/不可渲染 | **P1** |
| **D2** | `ChatRequest.use_personal_docs` | `bool=false`（08 个人文档 RAG 作用域） | `ChatRequest` 无此字段 | 前端无法开启「并入个人文档召回」开关（PersonalDocsPanel 未接该参数） | **P0**（历史已知断点） |
| **D3** | 会话历史 API（`/api/v1/history/*`，07） | 已实现 `SessionMeta`/`SessionDetail`/`SearchHit`/导出 | `client.ts` 未调用；`ChatSession` 仅内存 | 刷新/重进丢失历史；07 落库能力前端未消费 | **P1** |
| **D4** | 文档上传字段名 | `documents.py:46` 参数名 `files: list[UploadFile] = File(...)`（已核对） | `form.append("files", f)` | **已对齐**，无 422 风险（保留为一致性记录） | **P3**（已对齐） |
| **D5** | 生产 CORS | `server.cors.origins` 默认 `["*"]` | 生产直连需显式 origin | 生产跨域失败 | **P2** |
| **D6** | `ChatRequest.user_id` | 后端仍接受但**忽略**（用 JWT `CurrentUser`） | 前端不发送 | 无害但冗余字段 | **P3**（清理） |
| **D7** | `/api/v1/analyze` 鉴权 | 后端 `chat.py` 的 `analyze_endpoint` 仅依赖 `SessionDep`（DB 会话），**无 `CurrentUser`**；即 analyze 接口公开可调用、无需令牌；同文件 `chat_endpoint` 则有 `CurrentUser` | 前端 `analyze()` 经 `request()` 仍自动带 `Authorization`，但后端不校验 | 与 chat 不对称：聊天需鉴权、分析免鉴权，存在越权/滥用与无 `user_id` 作用域风险 | **P2**（安全一致性） |

> 说明：D1/D3 属「后端能力已具备、前端未接线」；D2/D4 属「前端开关/字段未对齐」；D5/D6 属配置/冗余清理。本模块只**登记**不修复；修复另立任务。
