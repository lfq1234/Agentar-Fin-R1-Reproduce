## 1. 总览与设计目标

08 为前端 03「个人文档与知识图谱」提供后端支撑：上传 → 解析 → 分块 → 向量化 → 落库 → 抽取图谱，并提供列表 / 删除 / 状态 / 图谱查询。

设计目标（与需求文档一致，并继承项目长期约定）：

- **复用 06 存储范式**：结构化业务数据落 **SQLite**，向量检索走 **DuckDB**（`ATTACH` 主库 + `list_cosine_distance`）。不重复造轮子。
- **不另开独立 SQLite 文件**：所有表统一建在 **03 主库 `agentar.db`**（与 `users` / `conversations` / `messages` / 07 会话历史同实例），不新建 `*.db` 分叉库。06 当前默认 `kb/knowledge.db` 是「独立文件」实现，08 显式改为「主库」方案——二者共用 DuckDB 机制但存储目标不同，读代码时注意区分（`config.kb.path` vs `config.db.sqlite_path`）。
- **嵌入统一走 01 `get_embedder()`**，切分复用 `06/04` 的 `chunking._split_into_chunks`，图谱抽取走 01 `get_model()`（可选、可降级）。

## 4. 数据模型与 DDL 收口

### 4.1 SQLite 主库表（DDL 收口 `app/db/schema/sqlite/main.sql`）

> 08 的四张结构化表**追加到 `main.sql`**（与 07 会话历史等同文件），随主库 `init_db()` / 部署脚本建表。DDL 文本与需求文档 §4.1 一致：

```sql
-- 八、personal_documents（个人文档元数据）
CREATE TABLE IF NOT EXISTS personal_documents (
    id          TEXT PRIMARY KEY,
    user_id     INTEGER NOT NULL,
    filename    TEXT NOT NULL,
    size        INTEGER NOT NULL,
    status      TEXT NOT NULL,        -- pending | parsing | done | error
    error       TEXT,
    uploaded_at TEXT NOT NULL,
    summary     TEXT,
    created_at  TEXT NOT NULL,
    updated_at  TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS ix_pdoc_user ON personal_documents(user_id);

-- 九、personal_doc_chunks
CREATE TABLE IF NOT EXISTS personal_doc_chunks (
    id       TEXT PRIMARY KEY,
    doc_id   TEXT NOT NULL,
    user_id  INTEGER NOT NULL,
    idx      INTEGER NOT NULL,
    text     TEXT NOT NULL,
    chapter  TEXT,
    FOREIGN KEY (doc_id) REFERENCES personal_documents(id) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS ix_pchunk_doc ON personal_doc_chunks(doc_id);

-- 十、personal_graph_nodes
CREATE TABLE IF NOT EXISTS personal_graph_nodes (
    id              TEXT PRIMARY KEY,
    doc_id          TEXT NOT NULL,
    user_id         INTEGER NOT NULL,
    label           TEXT NOT NULL,
    type            TEXT NOT NULL,
    source_doc_id   TEXT NOT NULL,
    properties_json TEXT
);
CREATE INDEX IF NOT EXISTS ix_pgn_doc ON personal_graph_nodes(doc_id);

-- 十一、personal_graph_edges
CREATE TABLE IF NOT EXISTS personal_graph_edges (
    id              TEXT PRIMARY KEY,
    doc_id          TEXT NOT NULL,
    user_id         INTEGER NOT NULL,
    source          TEXT NOT NULL,
    target          TEXT NOT NULL,
    label           TEXT NOT NULL,
    source_doc_id   TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS ix_pge_doc ON personal_graph_edges(doc_id);
```

> **外键级联**：依赖 `connection.py` 已开启的 `PRAGMA foreign_keys=ON` + `WAL`（见 §10）。删除 `personal_documents` 行时，SQLite 自动级联删 `personal_doc_chunks`；图谱表（`personal_graph_*`）当前为应用层级联（约简 DDL，避免跨表外键耦合），`store.delete_document()` 显式删四表（见 §6.3）。

### 4.2 DuckDB 向量表（DDL 收口 `app/db/schema/duckdb/personal_docs.sql`）

> **单一事实源**：本文件是 embeddings 表的唯一定义，`vector.py` 运行时读取并按 `CREATE TABLE` 切分建表（同 06 `knowledge.sql` → `sqlite_store._SCHEMA_STMTS` 的范式，避免 schema 漂移）。
> 因表建在 **SQLite 主库**（SQLite 无数组类型），`embedding` 以 **`TEXT`（JSON 数组）** 存储；DuckDB `ATTACH` 后检索时 `embedding::FLOAT[]` 转型——与 06 `chunks.embedding` 完全一致。

```sql
-- ============================================================
-- 08 个人文档 embeddings 建表脚本（DuckDB 引擎作用于 SQLite 主库）
-- 唯一事实来源：本文件；app/db/personal_docs/vector.py 读取本文件建表，不再内联。
-- 架构约定同 06：向量经 ATTACH 挂载主库做 list_cosine_distance 检索。
-- embedding 以 JSON 数组文本存储，检索时由 DuckDB 在 SQL 端转型为 FLOAT[]。
-- ============================================================

CREATE TABLE IF NOT EXISTS personal_doc_chunk_embeddings (
    chunk_id  TEXT PRIMARY KEY,        -- 关联 personal_doc_chunks.id
    doc_id    TEXT NOT NULL,
    user_id   INTEGER NOT NULL,
    embedding TEXT NOT NULL,           -- JSON 数组（FLOAT 列表）
    dim       INTEGER
);
```

> 索引由 DuckDB 引擎自建国前缀索引（同 06 `idx_pemb_doc` 风格），不在此文件内建。

## 5. 核心组件设计

### 5.1 `store.py` —— PersonalDocStore（SQLite 主库真相源）

职责：建表、写入（文档/块/图谱）、生命周期（list / delete / get_status / get_graph）、状态机。

- **连接**：复用 `config.db.sqlite_path`（默认 `./agentar.db`），`sqlite3.connect()` 直接连主库文件（与 07 异步引擎同文件，靠 WAL 协调）。`db.enabled=false` 时短路返回错误（沿用 `connection.py` 门控）。
- **读 DDL**：与 06 同范式，从 `app/db/schema/sqlite/main.sql` 读取 `personal_*` 表的 `CREATE TABLE` 语句并 `execute`（单一事实源，不内联）。
- **维度自适应**：实例化时 `SELECT MAX(dim) FROM personal_doc_chunk_embeddings` 做 seed（跨进程一致，同 06 `SQLiteKnowledgeStore._dim`）。

关键方法签名（草）：

```python
class PersonalDocStore:
    def __init__(self, db_path: str, *, embedder=None): ...
    def create_doc(self, doc_id, user_id, filename, size) -> None:        # status=pending
    def set_status(self, doc_id, status, error=None, summary=None) -> None
    def add_chunks(self, doc_id, user_id, chunks: list[Passage]) -> None  # 写 personal_doc_chunks
    def add_graph(self, doc_id, user_id, nodes, edges) -> None            # 写 personal_graph_*
    def list_docs(self, user_id) -> list[dict]: ...                       # 按 uploaded_at 倒序
    def get_doc(self, doc_id, user_id) -> dict | None: ...
    def delete_document(self, doc_id, user_id) -> None:                   # 应用层级联四表
    def get_graph(self, user_id) -> tuple[list[dict], list[dict]]: ...    # nodes, edges
```

### 5.2 `vector.py` —— DuckDB 向量检索

职责：把 chunk 文本向量化结果写入 embeddings 表，并对外提供近邻检索（供后续 RAG / 相似排序用，前端 03 MVP 暂不直接调用，但接口与 06 `retrieve` 对齐便于扩展）。

- **ATTACH 主库**（同 06 `store.py`）：

```python
import duckdb
con = duckdb.connect()                       # 内存控制连接
con.execute(f"ATTACH '{sqlite_path}' AS main (TYPE sqlite, READ_WRITE)")
con.execute(open("db/schema/duckdb/personal_docs.sql").read())  # 建 embeddings 表
```

- **写入**（embedder 产出 `list[float]` → `json.dumps` → TEXT）：

```python
con.execute(
    "INSERT OR REPLACE INTO main.personal_doc_chunk_embeddings "
    "(chunk_id, doc_id, user_id, embedding, dim) VALUES (?, ?, ?, ?, ?)",
    [chunk_id, doc_id, user_id, json.dumps(vec), len(vec)],
)
```

- **检索**（`list_cosine_distance`，同 06 `store.py` 检索 SQL）：

```python
rows = con.execute(
    "SELECT chunk_id, doc_id, "
    "1 - list_cosine_distance(embedding::FLOAT[], ?::FLOAT[]) AS similarity "
    "FROM main.personal_doc_chunk_embeddings "
    "WHERE user_id = ? ORDER BY similarity DESC LIMIT ?",
    [json.dumps(query_vec), user_id, top_k],
).fetchall()
```

### 5.3 `parser.py` —— 文本解析

- 支持扩展名：`.txt` / `.md` → 读文本（`errors="ignore"`）。
- 其他（`.pdf` / `.docx` / `.xlsx` 等二进制）→ 不解析，调用方标记 `status=error`，`error="暂不支持的文档类型：xxx（本期仅支持 .txt/.md）"`。不抛 500。
- Markdown 可顺带抽取一级/二级标题作为 chunk 的 `chapter`（透传给 `_split_into_chunks` 的 `chapter` 字段，非必须）。

### 5.4 切分（复用 06/04）

直接复用 `app.db.knowledge.chunking._split_into_chunks(text, max_chars=, overlap=)`，返回 `list[Passage]`（含 `.text` / `.chapter` 等）。参数来自 `personal_docs.chunk` 配置段（默认 `max_chars=600, overlap=80`）。

### 5.5 嵌入（复用 01）

`from app.model import get_embedder` 惰性获取，`embedder.embed([c.text for c in chunks]) -> list[list[float]]`。Store 内 `set_embedder` 便于单测注入 mock embedder（满足「无 torch 单测」）。

### 5.6 `graph_extract.py` —— 图谱抽取

- `model="auto"`：走 01 `get_model()`，提示词引导输出 `nodes[{id,label,type,properties}]` / `edges[{source,target,label}]`；解析失败回退启发式。
- `model="none"`：纯启发式——以文档名为 `Document` 根节点，正则抽取金融实体（机构/产品/条款/指标/人物/概念）作节点，按段落共现或首段提及建边。
- **降级不阻塞**：LLM 不可用、`graph.model=none`、或解析异常时仍 `status=done`，图谱可为空或启发式产出，不幻觉、不报错。
- 节点 `type` 建议取值（与前端一致）：`Document` / `Org` / `Product` / `Clause` / `Metric` / `Person` / `Concept`。

## 6. ingest 流水线（伪代码）

路由 `POST /api/v1/documents` 同步执行（MVP 小文件；大文件/多文件后台化留扩展点，状态轮询已预留）：

```python
async def upload(files, user_id):
    results = []
    for f in files:
        doc_id = uuid4().hex
        store.create_doc(doc_id, user_id, f.filename, f.size)   # status=pending
        try:
            store.set_status(doc_id, "parsing")
            text = parser.parse(f)                              # 二进制 → raise Unsupported
            chunks = _split_into_chunks(text, **chunk_cfg)      # 复用 06/04
            vecs = embedder.embed([c.text for c in chunks])     # 复用 01
            store.add_chunks(doc_id, user_id, chunks)           # 写 personal_doc_chunks
            vector.upsert(doc_id, user_id, chunks, vecs)        # 写 personal_doc_chunk_embeddings
            nodes, edges = graph_extract.extract(text, doc_id, user_id)  # LLM / 启发式
            store.add_graph(doc_id, user_id, nodes, edges)      # 写 personal_graph_*
            summary = (nodes[0].label if nodes else text[:120])
            store.set_status(doc_id, "done", summary=summary)
        except Unsupported as e:
            store.set_status(doc_id, "error", error=str(e))     # 不影响其他文件
        except Exception as e:
            store.set_status(doc_id, "error", error=f"处理失败：{e}")
        results.append(store.get_doc(doc_id, user_id))
    return {"documents": [to_camel(d) for d in results]}
```

> 单 doc 事务包裹（评审 I3 同 06），某文件失败不影响同批次其他文件。

## 8. 与前端 03 契约对齐

前端 03 类型用 **camelCase**，08 响应必须 camelCase（需求文档 §5 为精确 JSON 形状）：

- `PersonalDocument`: `id / filename / size / status / error / uploadedAt / summary`
- `GraphNode`: `id / label / type / sourceDocId / properties`
- `GraphEdge`: `id / source / target / label / sourceDocId`

实现：Pydantic v2 `model_config = ConfigDict(alias_generator=to_camel, populate_by_name=True)`，序列化按 alias 输出 camelCase；`properties` 为 `dict[str, str|int]`，允许缺省。

## 10. 复用关系与依赖（精确）

| 能力 | 复用来源 | 调用点 |
| --- | --- | --- |
| 嵌入 | `app.model.get_embedder()`（01） | `store._get_embedder` / `vector.py` |
| 切分 | `app.db.knowledge.chunking._split_into_chunks`（06/04 共享） | `parser` 后 |
| 图谱抽取 | `app.model.get_model()`（01） | `graph_extract.extract`（auto 模式） |
| 向量检索机制 | `06` DuckDB `ATTACH` + `list_cosine_distance` | `vector.py`（同 `store.py` 检索 SQL） |
| 主库文件/连接 | `config.db.sqlite_path` + `connection.py` 门控（03） | `store.py` 连主库 |
| DDL 单一事实源范式 | `06` `sqlite_store._SCHEMA_STMTS`（正则切 `CREATE TABLE`） | `store.py` / `vector.py` 读 `.sql` |

> 08 与 06 共享 DuckDB 机制但**存储目标不同**：06 → `kb/knowledge.db`（独立），08 → `agentar.db`（主库）。二者可经各自 DuckDB 连接 ATTACH 同一主库（06 不碰 08 表），本期单进程风险低；多 worker 时需协调单写者（见 §13）。

- **无 torch 单测**：`conftest` 注入 mock embedder（返回定长随机向量），覆盖 `ingest` / `list` / `delete` / `get_graph` / 向量检索；不依赖 GPU/模型（同 06 验收基线）。
- **降级用例**：`graph.model=none` → 上传仍 `done`、图谱启发式产出或不产出。
- **二进制用例**：`.pdf`/`.docx` → `status=error` 且 `error` 文案明确、非 500。
- **级联用例**：删除文档后 `personal_doc_chunks` / `embeddings` / `personal_graph_*` 同步清空。
- **作用域用例**：A 用户不能读 B 用户的文档/图谱。

## 13. 风险与缓解

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| DuckDB 单写者 | 进程内单连接串行写；多 worker uvicorn 共享主库需协调 | 本期单进程，风险低；08 与 06 错峰或统一经同一 DuckDB 连接管理 |
| 同步处理超时 | MVP 同步解析/嵌入，超大文件可能超时 | 状态轮询已预留，后续后台任务化 |
| 维度一致性 | 跨 embedder 切换需 rebuild（同 06 §3.4） | `embed_dim!=0` 时强制校验；`dim` 自适应 seed |
| 图谱质量 | 依赖 LLM 提示词与金融实体定义 | MVP 以「文档根+实体+共现边」为基线，质量随模型增强 |
| 层位混淆 | 06 独立库 vs 08 主库，读者易误判 | 文档/注释显式区分 `config.kb.path` 与 `config.db.sqlite_path` |
| 外键级联 | 图谱表未设跨表外键 | `delete_document` 应用层显式级联四表，覆盖级联缺口 |
