## 1. 概述与架构定位

### 1.1 在本项目中的层位
07 位于**03 后端基础层之上、与 06 知识库并列**的「可追溯 / 可复盘」横切层：

```
用户请求
  │
  ▼
03 路由/服务（chat_service.async chat）
  │   ├─ 主消息流落库：users / conversations / messages   ← 03 既有（07 复用，不重写）
  │   └─ 旁路 hook ──► 07 service 层写主库（session_meta / session_traces / trace_events）  ← 07 新增（同 03 主库实例）
  ▼
02 run() 多 Agent 流水线（Coordinator→RAG→专家→审核→风控）
  │   └─ RAG 检索 ──► 06 DuckDB 向量检索（同主库）        ← 06 既有（07 可选语义检索复用）
  ▼
AgentResult（reply + compliance_notes + risk_flags + 结构化字段）
  │   └─ get_session_for_review ──► raf 总结智能体（复盘）  ← 07 与 raf 协作（类比 06 喂 raf）
```

- **03 管「主消息流」**：user/assistant 两条消息的落库与 CRUD。
- **07 管「全链路轨迹 + 历史检索/复盘」**：在 03 之上补全中间步骤、tool、RAG 命中、审核/风控、错误，并提供回放/检索/导出/复盘。**07 本质是主库之上的常规分层模块——service 层（落库 / 查询 / 检索 / 导出）读写主库表，view 层（`SessionDetail` / `TurnDetail` / `SearchHit` 等聚合视图）组织跨表结果呈现给 API / 前端，不另开库、不分叉。**
- **06 是 07 可选的「向量检索机制提供方」**：开启 `history.semantic_search` 时，历史消息向量化后存入**主库 `history_embeddings` 表**（07 自有，与 03 同实例），经 DuckDB `ATTACH` 主库复用 06 的 `list_cosine_distance` 余弦检索能力——**不把历史塞进 06 知识库**，避免跨库分叉。

### 1.2 为什么这样定位（相对 03 主消息流、06 向量库）
| 方案 | 取舍 | 结论 |
|---|---|---|
| 在 03 内直接加细粒度 trace 表 | 03 已稳定，混入 trace 会膨胀其职责（DB 层 ≠ 可追溯层） | 07 独立层，复用 03 表，不污染 03 |
| 复用 06 DuckDB 存历史 | 06 是向量检索库，非结构化历史审计库；强行塞进 06 会混淆职责 | 07 的轨迹表建在主库，语义检索才委托 06 |
| 独立服务（如 Elasticsearch）或另开 DB 分叉 | 引入进程外依赖 / 与主库分叉，违背「统一主库、常规分层」原则 | 07 表与主库同实例，走 service 层，不另开库 |

07 与 03/06 同属「嵌入式单文件、进程内」范式，部署形态一致，迁移与运维成本低。

## 3. Schema 设计与写入策略

### 3.1 表结构（SQLite）
复用 03 的 `users` / `conversations` / `messages`；07 新增四表（**与 03 表同库同实例，跨表关联即可**），详见需求文档 §5 DDL。要点：

- `session_meta`：`conversation_id` 主键，扩展场景/标题/状态/统计；**不 ALTER 03 表**，独立表以保 03 契约稳定。
- `session_traces`：一次 `run()` 的轨迹头；`final_result` 存 JSON 序列化 `AgentResult`。
- `trace_events`：事件树，`parent_event_id` 层级；`meta_json` 灵活存 tool/RAG 命中溯源/错误；**append-only**（应用层禁 UPDATE/单条 DELETE）。
- `history_embeddings`（可选）：开启语义检索时存历史消息向量（JSON），含 `embedder_version` 字段以支撑 embedder 切换时的重建；经 DuckDB `ATTACH` 主库做余弦（同 06 范式）。

### 3.2 写入策略（控存储）
- **主消息流**：只存于 03 `messages`（07 不重复写）。
- **中间步骤**：存**摘要**（`summary_in` / `summary_out`）+ 必要结构化字段（`meta_json`），不存全文，降低敏感面与体积。
- **RAG 命中**：仅存溯源引用 + 分数（复用 06 `Passage` 字段：`doc_id/title/agency/domain/chapter/effective_date/version/score`），不重复存原文块。
- **错误**：存 `exc_type` / `message` / `traceback_summary`（前 N 行），不全量栈。

### 3.3 维度与一致性
- `history_embeddings.dim` 同 06 §3.4：首个向量决定维度，后续不一致抛错（语义检索路径）。
- 复用 03 异步引擎（`AsyncSession`）；07 表 creation 在 `history.enabled` 且 `build_on_startup` 时由 `init_history_db()` 建表（与 03 `init_db()` 同模式，`enabled` 门控）。

## 4. 轨迹采集集成点（hook 无侵入）

### 4.1 采集目标
把「每次和 AI 聊了什么」从 03 的「两条主消息」扩展为「一次完整、可回放的交互记录」。采集点：

1. **run() 入口/出口**：生成 `run_id`、记录 `scene` / `model` / `duration_ms` / `total_tokens` / `final_result`。
2. **02 流水线 step 钩子（演进）**：02 在 Coordinator→RAG→专家→审核→风控每个关键节点 emit 一个 step 事件（含 agent 名、输入/输出摘要、token、耗时）；07 `collect.py` 把它们转成 `trace_events`。
3. **tool 调用**：`lookup_knowledge` / `retrieve_documents` 的调用与结果（命中数、命中文档）作为 `tool_call` / `rag_hit` 事件。
4. **错误**：任一节点抛 `ModelInvokeError` 或其他异常，记 `error` 事件，`status=error`。

### 4.2 集成方式（无侵入、旁路、降级）
- **装饰器/上下文管理器**：`app/services/history/hooks.py` 的 `trace_session` 包裹 03 `chat_service.chat`（或 02 `run()`）。伪代码：

```python
# app/services/history/hooks.py
def trace_session(get_user=lambda kw: kw.get("user_id"),
                  get_conv=lambda kw: kw.get("conversation_id")):
    def deco(fn):
        @wraps(fn)
        async def wrapper(*a, **kw):
            if not _store or not _store.enabled:
                return await fn(*a, **kw)          # 总开关关 -> 完全旁路
            run_id = uuid4().hex
            t0 = time.monotonic()
            try:
                result = await fn(*a, **kw)
                status, err = "ok", None
            except Exception as e:
                status, err = "error", e
                raise                                # 主链路异常照常抛出
            finally:
                # 旁路异步写入，不阻塞返回
                _write_trace_async(run_id, get_user(kw), get_conv(kw),
                                   result, err, t0)
            return result
        return wrapper
    return deco
```

- **旁路异步写入**：`_write_trace_async` 把 trace 构造与 DB 写入提交到线程/任务，主协程立即 `return result`；写入失败按 `fail_mode` 处理（`silent` 丢弃 / `local` 落兜底文件）。
- **降级契约**：`history.enabled=false` 或 DB 不可用时，`get_history_store()` 返回 `NoopHistoryStore`，所有方法为空操作，主链路 `reply` 不受影响（与 03 `db.enabled` 短路一致）。
- **与 03 协同**：03 `chat_service` 已落主消息；07 hook 在其外层，避免重复落主消息，只补 `session_traces` + `trace_events` + `session_meta` 更新。

### 4.3 演进路径（与 02 协作门禁）
- **首版（02 未暴露 step 钩子）**：`trace_events` 仅含「头 + user/assistant 主消息事件」，`record_traces` 退化为记录主消息级事件；满足「记录每次聊了什么」的基本可追溯。
- **增强版（02 扩展 step 钩子后）**：02 在每个 agent 节点 emit step，`collect.py` 补全 `tool_call` / `rag_hit` / `review` / `risk` / `error` 细粒度事件，达成完整回放。
- 该门禁在需求文档 §9.1 记录；07 接口预留 `events: list[TraceEvent]` 入参，02 就绪即填。

## 5. 历史检索

### 5.1 关键词检索（keyword_search）
- 在 `messages.content` 与 `trace_events.summary_in/out` / `meta_json` 上做匹配。
- 实现：`sqlite` 原生 `LIKE` 或启用 SQLite FTS5（`CREATE VIRTUAL TABLE ... USING fts5`）做 BM25；带 `user_id` / `scene` / `start` / `end` 过滤。
- 返回 `SearchHit`：`conversation_id` / `turn_id` / `event_id` / `snippet` / `score` / `created_at`。

### 5.2 可选语义检索（semantic_search，复用 06）
- 开关 `history.semantic_search=true` 时启用。
- 流程：历史消息（user + assistant 摘要）经 01 `get_embedder()` 向量化 → 写入**主库 `history_embeddings` 表**（07 自有，与 03 同实例）→ 查询时 DuckDB `ATTACH` 主库，复用 06 的 `list_cosine_distance` 余弦机制召回（向量不写入 06 知识库）。
- 受 06 §3.4 维度一致约束；跨 embedder 切换需 `rebuild` `history_embeddings`。
- 不引入独立向量服务，复用 06 现有能力（与 06 §1.2 选型一致）。

### 5.3 检索结果去隐私
- 检索返回片段前先走 `redact.py` 脱敏；非本人（且非管理员）查询返回空（权限边界）。

## 6. 回放与导出

### 6.1 回放（get_session / get_turn）
- `get_session`：读 03 `messages`（按时间序）+ 07 `session_traces` + `trace_events` 树，组装 `SessionDetail`（可前端树状展示每次对话的完整链路）。
- `get_turn`：取单轮（一次 user→assistant）的 `trace_events` 子树，呈现「输入 → Coordinator 路由 → RAG 检索 → 专家作答 → 审核 → 风控 → 最终回复」。

### 6.2 导出（export_session）
- `fmt="md"`：渲染为复盘文档——会话元信息（场景/时间/模型/token）+ 主消息流 + 每轮 trace（agent 步骤、tool、RAG 命中溯源、审核/风控、耗时）。
- `fmt="json"`：原始结构化（便于二次处理/审计）。

### 6.3 复盘上下文（get_session_for_review，供 raf）
- 把一次会话组织成带溯源的结构化上下文（类比 06 `format_passages`）：聚合「用户诉求 + 各 agent 结论 + RAG 依据 + 审核/风控」，输出文本交给 **raf 总结智能体**生成复盘摘要/改进建议。
- 07 与 raf 职责边界：07 只「记录 + 组织成结构化上下文」；「总结成复盘」是 raf 的 LLM 职责（与 06 §FR9 一致）。

## 7. 留存与清理

- `retention_days`（默认 180）：`purge_before(before_date)` 清理更早的 `session_traces` / `trace_events` / `session_meta`；`history_embeddings` 一并清。
- `purge_cascade=false`（默认）：仅清 07 轨迹，**保留 03 主消息**（用户对话不可随意删）；`cascade=true` 时联动删 03 消息（谨慎，默认关，受合规约束）。
- `delete_session`：删单会话的 07 轨迹；权限校验（仅本人/管理员）。
- 清理为低频运维操作，建议脚本/定时任务触发，不在请求链路同步执行。

---

## 8. 隐私与安全

- **脱敏（redact.py）**：`pii_redact=true` 时，落库前对手机号/身份证/银行卡/邮箱等做掩码（`138****1234`）；正则集可配，白名单避免误伤（如合规条款编号）。
- **访问控制**：所有查询以 `user_id` 归属隔离；`allow_admin_all=true` 允许运维跨用户审计（仅管理员角色）。
- **防篡改（append-only）**：`trace_events` 应用层禁 UPDATE/单条 DELETE；写仅 INSERT + `created_at`；整体清理仅经 `delete_session` / `purge_before`。
- **最小化**：中间步骤存摘要、RAG 命中仅存溯源，降低敏感面。
- **合规**：`retention_days=0` 表示永久留存（金融场景可能要求）；默认值待法务确认（需求 §9.6）。

## 9. 与多智能体集成（raf 复盘）

- **采集集成**：`trace_session` hook 包裹 02 `run()` / 03 `chat_service`，无侵入记录全链路（§4）。
- **复盘集成**：`get_session_for_review` 产出结构化上下文 → raf 总结智能体生成复盘（类比 06 把 `Passage` 喂 raf）。07 与 raf 分工明确（§6.3）。
- **RAG 命中溯源一致性**：07 的 `rag_hit` 事件复用 06 `Passage` 溯源字段（`doc_id/title/agency/domain/chapter/effective_date/version/score`），保证 raf 引用与 06 一致。
- **降级契约**：07 不可用时主链路正常（fail_mode），raf 复盘缺失该会话历史时如实声明「无历史依据」。

## 12. 测试策略

- **采集**：mock `run()` 返回含多 agent 步骤的假 `AgentResult`，断言 `session_traces` + `trace_events` 正确写入；`record_traces=false` 时仅头。
- **降级**：`history.enabled=false` → `NoopHistoryStore`，主链路返回正常；DB 不可用时 `fail_mode=silent` 不抛错。
- **查询/回放**：`get_session` 组装主消息 + trace 树；`get_turn` 取单轮。
- **检索**：`keyword_search` 命中片段；`semantic_search`（开启时）经 06 余弦召回。
- **导出/复盘**：`export_session` 产出 md/json；`get_session_for_review` 产出 raf 上下文。
- **留存**：`purge_before` 清理更早轨迹，`purge_cascade=false` 保留 03 主消息。
- **隐私**：`pii_redact=true` 落库掩码；非本人访问返回空。
- 全部单测在**无 `OPENAI_API_KEY`、无 vLLM、`history.enabled` 可关** 环境下可跑（靠 mock `run()`）。

## 13. 风险与权衡

| 风险 | 权衡 / 缓解 |
|---|---|
| 02 未暴露 step 钩子，细粒度 trace 暂不可得 | 首版记「头+主消息」，预留 events 入参；02 扩展后增强（§4.3） |
| 旁路异步写入可能丢失（进程崩溃） | `fail_mode=local` 落兜底文件；会话级可追溯非强一致，可接受最终一致 |
| 轨迹库膨胀 | 中间步骤存摘要、RAG 仅存溯源、`retention_days` 清理（§3.2/§7） |
| 语义检索引入 embedder 依赖 | 默认关（`semantic_search=false`），复用 06，不新增服务（§5.2） |
| 隐私合规 | 脱敏 + append-only + 权限 + 留存可配（§8） |
| 与 03 `agent_traces` 预留重复 | 命名对齐 `session_traces`/`trace_events`，评审确认（需求 §9.2） |
