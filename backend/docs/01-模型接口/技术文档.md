### 3.2 抽象接口（`model/base.py`）
```python
from abc import ABC, abstractmethod
from dataclasses import dataclass

@dataclass
class ModelConfig:
    model_type: str          # 固定 "openai_chat"
    model_name: str
    api_key: str
    base_url: str
    temperature: float = 0.3
    stream: bool = False
    timeout: int = 120
    max_retries: int = 2

class ModelInterface(ABC):
    def __init__(self, cfg: ModelConfig): ...
    @abstractmethod
    def build_agentscope_config(self) -> dict:
        """返回 AgentScope openai_chat 模型配置字典。"""
    @abstractmethod
    def generate(self, prompt: str, **kwargs) -> str: ...
```
> 异常：`generate()` 在 key 缺失 / 网络错误 / 超时时抛出 `ModelInvokeError`（见 §3.6、§3.3）。

### 3.3 `ApiModel` / `LocalModel`（实现要点）
两者仅 `base_url` / `api_key` 来源不同（`ApiModel` 取 `config.model.api`，`LocalModel` 取 `config.model.local`）。`build_agentscope_config()` 统一产出：
```python
{
    "model_type": "openai_chat",
    "config_name": self.cfg.model_name,
    "model_name": self.cfg.model_name,
    "api_key": self.cfg.api_key,
    "base_url": self.cfg.base_url,
    "temperature": self.cfg.temperature,
    "stream": self.cfg.stream,
}
```
> **字段名门禁（评审问题7）**：`openai_chat` 的字段名（`config_name` vs `model_name`）随 AgentScope 版本变化。**编码前必须 `pip show agentscope` + 官方 tutorial 锁定字段名，并将确认结果回填本节、删除本提示**，否则验收"返回合法 openai_chat 配置"无法判定。

`generate()` 实现策略（评审问题3，已决策）：本期 `generate()` **直连 OpenAI 兼容端点**——`ApiModel` 用真实 key 调云端 `base_url`，`LocalModel` 同样用 OpenAI 兼容客户端指向 vLLM 的 `http://localhost:8000/v1`；`build_agentscope_config()` 仅作为给后续 `services/` AgentScope 编排的"配置导出"，不影响 `generate()` 行为。

`ModelInvokeError` 触发（评审问题4）：`generate()` 在以下场景抛出 `ModelInvokeError`：
- `api_key` 为占位/空（`local` 的 `EMPTY` 在直连场景下视为缺失）；
- 网络错误（连接失败 / 5xx / 超时）；
- 超过 `max_retries` 仍失败。

### 3.4 工厂（`model/factory.py`）
```python
from app.config import config
from app.model.exceptions import ModelInvokeError
from app.model.api.openai_api import ApiModel
from app.model.local.vllm_local import LocalModel

def get_model() -> ModelInterface:
    mode = config.model.get("mode")
    if mode not in ("api", "local"):                       # 评审问题5：非法 mode 显式报错
        raise ValueError(f"model.mode 必须是 'api' 或 'local'，收到: {mode!r}")
    section = dict(config.model.get(mode))                 # mode=local -> model.local，否则 model.api
    # 评审问题1：合并顶层全局默认 timeout / max_retries，子段优先
    for key in ("timeout", "max_retries"):
        if key not in section and key in config.model:
            section[key] = config.model[key]
    cls = LocalModel if mode == "local" else ApiModel
    return cls(ModelConfig(**section))
```

### 3.7 嵌入接口（01 为 04 的 RAG 向量化扩展）

> 来源：04 技术文档 §12「01 待修改清单」。04 的 `retrieval.py`（扩展自 02）需要把文本转为向量，
> 嵌入模型能力由 **01 扩展提供**，04 调用 `get_embedder()` 完成向量化，不自管嵌入模型。

嵌入分支与文本生成分支**完全平行**：同样的 api / local 双模式、同样的物理分离类、同样的
工厂分发与全局默认合并逻辑，仅调用端点从 `chat.completions` 换成 `embeddings`。

**抽象层（`model/base.py`）**：
```python
@dataclass
class EmbedConfig:
    model_type: str          # 固定 "openai_embedding"
    model_name: str
    api_key: str
    base_url: str
    timeout: int = 120
    max_retries: int = 2

class EmbedderInterface(ABC):
    def __init__(self, cfg: EmbedConfig): ...
    @abstractmethod
    def build_agentscope_config(self) -> dict:
        """返回 AgentScope openai_embedding 配置字典。"""
    @abstractmethod
    def embed(self, texts: list[str]) -> list[list[float]]: ...
```

**实现（`model/api/embed_openai.py` / `model/local/embed_local.py`）**：
- `ApiEmbedder`：`api_key` 为占位/空/`${...}` 字面量时，调用 `embed()` 抛 `ModelInvokeError`（与 `ApiModel` 一致）。
- `LocalEmbedder`：`api_key` 的 `EMPTY` 视为占位直连透传（与 `LocalModel` 一致），仅网络失败/超时抛 `ModelInvokeError`。
- 两者 `embed()` 均调 OpenAI SDK 的 `client.embeddings.create(model=..., input=texts)`，返回 `[item.embedding for item in resp.data]`（与输入等长的向量列表）。
- `build_agentscope_config()` 统一产出 `{"model_type": "openai_embedding", "config_name": ..., "model_name": ..., "api_key": ..., "base_url": ...}`。

**工厂（`model/factory.py`）**：
```python
def get_embedder() -> EmbedderInterface:
    emb_cfg = config.emb                       # Config 属性访问
    mode = emb_cfg.get("mode")
    if mode not in ("api", "local"):
        raise ValueError(f"emb.mode 必须是 'api' 或 'local'，收到: {mode!r}")
    section = dict(emb_cfg.get(mode))
    for key in ("timeout", "max_retries"):     # 合并顶层全局默认，子段优先
        if key not in section and key in emb_cfg:
            section[key] = emb_cfg[key]
    cls = LocalEmbedder if mode == "local" else ApiEmbedder
    return cls(EmbedConfig(**section))
```

**配置（`config/config.yaml` 新增顶层 `emb` 段，形态对齐 `model` 段）**：
```yaml
emb:
  mode: api
  timeout: 120
  max_retries: 2
  api:
    model_type: openai_embedding
    model_name: text-embedding-3-small
    api_key: ${OPENAI_API_KEY}
    base_url: https://api.openai.com/v1
  local:
    model_type: openai_embedding
    model_name: bge-small-zh
    api_key: EMPTY
    base_url: http://localhost:8001/v1
```

## 4. 实现要点与步骤
1. **`config/` 配置落地**：YAML 加载器递归替换 `${ENV_VAR}`；在 `config.yaml` 补齐 `model` 三段（含顶层 `timeout`/`max_retries`），同步 `config.example.yaml`。
2. **`model/base.py`**：定义 `ModelConfig`（dataclass）与 `ModelInterface`（ABC）。
3. **`model/exceptions.py`**：定义 `ModelInvokeError(RuntimeError)`。
4. **`model/api/openai_api.py`**：`ApiModel(ModelInterface)`，构造接收 `ModelConfig`；`generate()` 用 `openai` 客户端直连云端 `base_url`，失败时抛 `ModelInvokeError`。
5. **`model/local/vllm_local.py`**：`LocalModel(ModelInterface)`，逻辑同 `ApiModel`，端点为本地 vLLM；`api_key == "EMPTY"` 时直连场景视为缺失并抛 `ModelInvokeError`。
6. **`model/factory.py`**：`get_model()` 校验 `mode` + 合并全局默认 + 返回实现（见 §3.4）。
7. **`model/__init__.py`**：导出 `ModelInterface`、`ModelConfig`、`get_model`、`ModelInvokeError`，以及嵌入扩展的 `EmbedderInterface`、`EmbedConfig`、`get_embedder`。
8. **嵌入扩展（01 为 04 扩展）**：`model/base.py` 新增 `EmbedConfig`/`EmbedderInterface`；`model/api/embed_openai.py`、`model/local/embed_local.py` 分别实现 `ApiEmbedder`/`LocalEmbedder`（`embed()` 调 `embeddings.create`）；`model/factory.py` 新增 `get_embedder()`（与 `get_model` 平行：校验 `emb.mode` + 合并全局默认）；`config.yaml`/`config.example.yaml` 新增顶层 `emb` 段（对齐 `model` 段）。
9. **`tests/test_model.py` / `tests/test_embedder.py`**：覆盖工厂分发、mode 校验、配置产出、异常（见 §5）。
10. **编码前门禁**：`pip show agentscope` 锁定 `openai_chat` / `openai_embedding` 字段名并回填 §3.3 / §3.7。

## 6. 风险与待定
- **AgentScope 字段名差异**：`openai_chat` 配置键随版本变化，已列为**编码前门禁**（§3.3、§3.6），核实后回填，避免硬编码错键。
- **本地模式依赖 vLLM 服务**：`local` 模式需外部已起 vLLM 端点；开发期先用 `api` 模式把链路跑通，再切 `local`。
- **`generate()` 已被决策为直连**：不再悬而未决；主链路由后续 `services/` 经 AgentScope 调用时复用 `build_agentscope_config()` 导出（评审问题3 已闭环）。
- **超时 / 重试**：本期 `timeout`/`max_retries` 透传配置并经工厂合并（§3.4），具体重试策略后续在 `services/` 统一处理。
