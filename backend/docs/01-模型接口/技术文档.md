## 1. 需求背景与目标
对应需求文档：在 `app/model/` 建立统一模型接口层，支持 API 与本地（vLLM）两种调用方式、物理分离、配置切换、工厂分发。目标是把"模型怎么调"和"Agent 怎么编排"解耦，让 `services/` 只依赖一个抽象接口。

## 3. 接口 / 数据结构变更

### 3.1 目录结构（新增）
```
app/model/
├── __init__.py            # 导出 ModelInterface, get_model
├── base.py                # ModelInterface(abc)：抽象接口
├── factory.py             # get_model() -> ApiModel | LocalModel
├── api/
│   ├── __init__.py
│   └── openai_api.py      # ApiModel：云端 OpenAI 兼容
└── local/
    ├── __init__.py
    └── vllm_local.py      # LocalModel：本地 vLLM OpenAI 兼容
```

### 3.2 抽象接口（`model/base.py`）
```python
from abc import ABC, abstractmethod
from dataclasses import dataclass

@dataclass
class ModelConfig:
    model_type: str          # 固定 "openai_chat"
    model_name: str
    api_key: str
    base_url: str
    temperature: float = 0.3
    stream: bool = False
    timeout: int = 120
    max_retries: int = 2

class ModelInterface(ABC):
    def __init__(self, cfg: ModelConfig): ...
    @abstractmethod
    def build_agentscope_config(self) -> dict:
        """返回 AgentScope openai_chat 模型配置字典。"""
    @abstractmethod
    def generate(self, prompt: str, **kwargs) -> str: ...
```

### 3.3 `ApiModel` / `LocalModel`（实现要点）
两者仅 `base_url` / `api_key` 来源不同（`ApiModel` 取 `config.model.api`，`LocalModel` 取 `config.model.local`），`build_agentscope_config()` 统一产出：
```python
{
    "model_type": "openai_chat",
    "config_name": self.cfg.model_name,
    "model_name": self.cfg.model_name,
    "api_key": self.cfg.api_key,
    "base_url": self.cfg.base_url,
    "temperature": self.cfg.temperature,
    "stream": self.cfg.stream,
}
```

### 3.4 工厂（`model/factory.py`）
```python
from app.config import config
from app.model.api.openai_api import ApiModel
from app.model.local.vllm_local import LocalModel

def get_model() -> ModelInterface:
    section = config.model["local"] if config.model["mode"] == "local" else config.model["api"]
    cls = LocalModel if config.model["mode"] == "local" else ApiModel
    return cls(ModelConfig(**section))
```

## 4. 实现要点与步骤
1. **`config/` 配置落地**：确认 `app/config/__init__.py` 的 YAML 加载器能递归替换 `${ENV_VAR}`（见总文档 §4.3）；在 `config.yaml` 补齐 `model` 三段，并同步 `config.example.yaml`。
2. **`model/base.py`**：定义 `ModelConfig`（dataclass）与 `ModelInterface`（ABC），含 `build_agentscope_config()` 与 `generate()`。
3. **`model/api/openai_api.py`**：`ApiModel(ModelInterface)`，构造时接收 `ModelConfig`，实现两方法（云端 `base_url`）。
4. **`model/local/vllm_local.py`**：`LocalModel(ModelInterface)`，逻辑同 `ApiModel`，仅端点为本地 vLLM。
5. **`model/factory.py`**：`get_model()` 按 `config.model["mode"]` 选择实现。
6. **`model/__init__.py`**：导出 `ModelInterface`、`ModelConfig`、`get_model`，供 `services/` 后续 import。
7. **单测**：`tests/test_model.py` 覆盖 factory 分发与两种实现的配置产出。

> 注：AgentScope v1 的 `openai_chat` 字段名以安装版本 tutorial 为准（编码前 `pip show agentscope` 核实）；当前字段为设计预期，可能需微调。

## 6. 风险与待定
- **AgentScope 字段名差异**：`openai_chat` 的配置键（如 `config_name` vs `model_name`）随版本变化，编码前核实，避免硬编码错键。
- **本地模式依赖 vLLM 服务**：`local` 模式需要外部已起 vLLM 端点；开发期先用 `api` 模式把链路跑通，再切 `local`（见总文档 §10、§13）。
- **`generate()` 的底层实现**：是直连 OpenAI SDK 还是经 AgentScope runtime 调，取决于 `services/` 编排方式；本期 `generate()` 可作为兜底直连，主链路由 `services/` 经 AgentScope 调用（待 §02 服务层确认）。
- **超时 / 重试**：`timeout`、`max_retries` 本期先透传配置，具体重试策略在 `services/` 统一处理。
