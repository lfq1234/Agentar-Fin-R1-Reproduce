## 1. 背景与诉求
后端推理需要一个**统一的模型调用入口**，同时支持两种部署形态：

- **API 模式**：调用云端 / 第三方 OpenAI 兼容端点（如 gpt-4o、DeepSeek、自建兼容服务），密钥通过环境变量注入。
- **本地模式**：消费 `agentar-fin-r1/training` 产出的 Qwen3-8B + LoRA 检查点，由本地 vLLM 起一个 OpenAI 兼容服务（`http://localhost:8000/v1`），后端以 OpenAI 兼容协议访问。

两种模式的**上层代码必须只有一份**：靠配置切换，而不是写两套分支逻辑。当前仓库 `services/inference.py` 与 `agent/runner.py` 全是 stub，尚未接入任何真实模型，因此本次先把"模型接口层"独立抽出来，作为后续 `services/` 多 Agent 编排的依赖底座。

## 2. 目标与范围
- 目标 1：在 `app/model/` 下建立模型接口层，对外暴露统一的 `ModelInterface`。
- 目标 2：`model/api/` 与 `model/local/` 两个文件夹**物理分离**两种调用实现，互不影响、互不耦合；两者**共享同一抽象接口 `ModelInterface` 与同一份 `build_agentscope_config` 字段模板**，但具体实现各自成类、各自文件夹（评审问题8 修复）。
- 目标 3：通过 `config.yaml` 的 `model.mode: api | local` 一键切换，无需改代码。
- 目标 4：`model/factory.py` 按 `mode` 返回对应实现，调用方（未来 `services/`）只依赖抽象接口。
- 不在本次范围内：AgentScope 多 Agent 编排、真实 prompt、流式 SSE、`db/` 持久化。

## 3. 功能 / 非功能要求
- 功能点：
  - 抽象接口 `ModelInterface`：`build_agentscope_config() -> dict`（产出 AgentScope 的 `openai_chat` 模型配置）与 `generate(prompt, **kw) -> str`（**本期直连 OpenAI 兼容端点**，评审问题3 已决策）。
  - `ApiModel`（API 模式）：基于云端 `base_url` + 真实 `api_key` 构造配置；`base_url` 由配置决定（不硬编码为 OpenAI），以支持任意 OpenAI 兼容服务。
  - `LocalTransformerModel`（本地模式）：后端进程内用 transformers 直接加载 `model_path` 权重并推理，不依赖任何外部推理端点；与 `ApiModel` 共用同一抽象接口 `ModelInterface`，但实现物理分离（各自文件夹、各自类）。
  - `get_model()` 工厂：读取 `config.model.mode`，**校验 mode 合法性**（非法值报错，评审问题5），返回 `ApiModel` 或 `LocalTransformerModel`。
- 非功能约束：
  - 配置（密钥）不落库：`api_key` 等以 `${ENV_VAR}` 形式在 YAML 中引用，加载时替换。
  - 可测性：两种实现可独立单测；`mode` 切换与校验逻辑可单测。
  - 统一异常：两种模式下的调用失败应抛出可识别的异常 `ModelInvokeError`（key 缺失 / 网络错误 / 超时），便于上层处理（评审问题4 已补设计）。
  - 超时 / 重试生效：顶层 `model.timeout` / `model.max_retries` 作为全局默认，由工厂合并进所选子段，避免配置形同虚设（评审问题1 修复）。

## 4. 验收标准
- [ ] `app/model/base.py` 定义 `ModelInterface` 抽象类，含 `build_agentscope_config()` 与 `generate()`。
- [ ] `app/model/api/openai_api.py` 实现 `ApiModel`，读取 `config.model.api` 段（`base_url/api_key/model_name/temperature`）。
- [ ] `app/model/local/transformer_local.py` 实现 `LocalTransformerModel`，读取 `config.model.local` 段（进程内 transformers 直载 `model_path`）。
- [ ] `app/model/exceptions.py` 定义 `ModelInvokeError`，并在 `generate()` 失败场景抛出。
- [ ] `app/model/factory.py` 的 `get_model()` 在 `mode=api` 时返回 `ApiModel`、`mode=local` 时返回 `LocalTransformerModel`；`mode` 非法时抛 `ValueError`。
- [ ] `config.yaml` 含完整的 `model.api` 与 `model.local` 两段，且 `model.mode` 可切换；顶层 `timeout`/`max_retries` 经工厂合并生效；`config.example.yaml` 同步提供脱敏模板。
- [ ] 单测文件 `tests/test_model.py` 覆盖：工厂按 `mode` 返回正确类型；非法 `mode` 抛 `ValueError`；两种实现 `build_agentscope_config()` 产出合法的 `openai_chat` 配置字典（字段名以编码前核实为准）；`ModelInvokeError` 在 key 缺失 / 网络失败时可识别（评审问题2 修复文件名对齐）。
