## 1. 总体方案

在现有 `users` 表上补齐身份字段，引入 **pwdlib（Argon2/Bcrypt）哈希 + PyJWT（HS256）Bearer** 的轻量鉴权，与 `full-stack-fastapi-template` 范式保持一致。核心改动是**把 `user_id` 的信任来源从「请求体/查询参数」切换为「JWT 解析出的当前用户」**，从而顺带闭环 08 的越权风险。

数据层隔离**不需要新建**：经核查，03 `conversations` 有 `user_id` FK + `ON DELETE CASCADE`；08 的 `personal_documents / personal_doc_chunks / personal_graph_nodes / personal_graph_edges` 以及 DuckDB 向量表 `personal_doc_chunk_embeddings` 全部带 `user_id` 列并建索引，向量检索 `WHERE e.user_id = ?` 已按用户过滤。本次仅替换 `user_id` 的注入点。

## 3. 数据模型变更

    id          INTEGER PRIMARY KEY,

## 4. 鉴权核心（`app/core/security.py`）

直接对齐模板 `core/security.py`：

```python
from datetime import UTC, datetime, timedelta
import jwt
from pwdlib import PasswordHash
from pwdlib.hashers.argon2 import Argon2Hasher
from pwdlib.hashers.bcrypt import BcryptHasher
from app.config import config

password_hash = PasswordHash((Argon2Hasher(), BcryptHasher()))
ALGORITHM = "HS256"

def get_secret_key() -> str:
    key = config.get("security", {}).get("secret_key") or ""
    if not key:
        raise RuntimeError("security.secret_key 未配置（请通过环境变量 AUTH_SECRET_KEY 注入）")
    return key

def create_access_token(subject: str | int, expires_delta: timedelta) -> str:
    expire = datetime.now(UTC) + expires_delta
    return jwt.encode({"exp": expire, "sub": str(subject)}, get_secret_key(), algorithm=ALGORITHM)

def verify_password(plain: str, hashed: str) -> bool:
    ok, _ = password_hash.verify_and_update(plain, hashed)
    return ok

def get_password_hash(password: str) -> str:
    return password_hash.hash(password)
```

> `config` 为本项目自定义加载器（`app/config/__init__.py`，嵌套 dict + `${ENV}` 替换）。`secret_key` 从 `config.yaml` 的 `${AUTH_SECRET_KEY}` 读取，缺失即启动失败（S3）。

## 5. 当前用户依赖（`app/routes/deps.py`）

对齐模板 `api/deps.py`，但 `get_db` 复用本项目 `app/db/models.get_db`：

```python
from fastapi import Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer
from jwt.exceptions import InvalidTokenError
from pydantic import ValidationError
from sqlmodel import Session
from app.core import security
from app.config import config
from app.db.models import User, get_db

reusable_oauth2 = OAuth2PasswordBearer(tokenUrl="/api/v1/auth/login/access-token")
SessionDep = Depends(get_db)            # 本项目 get_db 返回 AsyncSession
TokenDep = Depends(reusable_oauth2)

async def get_current_user(session: SessionDep, token: TokenDep) -> User:
    try:
        payload = jwt.decode(token, security.get_secret_key(), algorithms=[security.ALGORITHM])
        user_id = int(payload.get("sub"))
    except (InvalidTokenError, ValidationError, TypeError, ValueError):
        raise HTTPException(status_code=status.HTTP_403_FORBIDDEN, detail="凭证无效或已过期")
    user = await session.get(User, user_id)
    if not user:
        raise HTTPException(status_code=404, detail="用户不存在")
    if not user.is_active:
        raise HTTPException(status_code=400, detail="账号已停用")
    return user

CurrentUser = Depends(get_current_user)
```

> 注意：本项目 `get_db` 为异步（`AsyncSession`），`session.get` 需 `await`；模板为同步，写法略有差异但语义一致。

## 6. 路由实现

### 6.1 `app/routes/auth.py`
```python
router = APIRouter(prefix="/v1/auth", tags=["auth"])

@router.post("/register", response_model=UserPublic, status_code=201)
async def register(user_in: UserCreate, session: SessionDep):
    if await crud.get_by_username(session, user_in.username):
        raise HTTPException(status_code=409, detail="账号已存在")
    return await crud.create_user(session, user_in)

@router.post("/login/access-token")
async def login_access_token(form: Annotated[OAuth2PasswordRequestForm, Depends()], session: SessionDep):
    user = await crud.authenticate(session, user_in.username, form.password)
    if not user:
        raise HTTPException(status_code=400, detail="账号或密码错误")
    if not user.is_active:
        raise HTTPException(status_code=400, detail="账号已停用")
    minutes = int(config.get("security", {}).get("access_token_expire_minutes", 60))
    token = security.create_access_token(user.id, timedelta(minutes=minutes))
    return {"access_token": token, "token_type": "bearer"}

@router.get("/me", response_model=UserPublic)
async def read_me(current_user: CurrentUser):
    return current_user
```

### 6.2 `app/crud/user.py`（镜像模板 `crud.py`）
- `get_by_username(session, username)` → 唯一查询。
- `authenticate(session, username, password)` → 取用户、`security.verify_password` 校验，返回 `User | None`（统一返回 None，不区分账号/密码错，FR9）。
- `create_user(session, user_in)` → 哈希密码后 `User(...)`，提交返回 `UserPublic`。

### 6.3 既有端点改造（要点）
- **chat.py**：`chat_endpoint(req: ChatRequest, current_user: CurrentUser, db=Depends(get_db))` → 调 `chat_service(req, db, user_id=current_user.id)`。删除 `ChatRequest.user_id`。
- **documents.py**：5 个端点签名 `user_id: int = Query(1)` 改为 `current_user: CurrentUser`，函数体内 `user_id = current_user.id`。
- **history.py**：`user_id: str = Query(...)` 改为 `current_user: CurrentUser`，内传 `str(current_user.id)`。
- **rag/retrieve**：`RagRetrieveRequest` 去掉 `user_id`，路由内以 `current_user.id` 调用。
- **main.py**：`app.include_router(auth_routes.router, prefix="/api")`。

### 6.4 `chat_service.py` 去除假用户
删除：
```python
user = await db.get(User, req.user_id)
if user is None:
    user = User(id=req.user_id, username=f"user_{req.user_id}")  # ← 删除
    db.add(user); await db.commit(); await db.refresh(user)
```
改为：登录保证 `User` 存在，`user_id=current_user.id` 直接取用；`use_personal_docs` 仍仅在 `user_id is not None` 时生效（现在恒成立）。

## 8. 前端改造（概要）

位置：`frontend/src/`
1. **新增 `auth` 模块**：`api/client.ts` 加 `register/login/me`；`localStorage` 读写 token（`agentar_token`）。
2. **请求拦截**：`post()` 统一追加 `Authorization: Bearer <token>`；`401` 时清除 token 并跳登录页。
3. **登录/注册页**：新增 `LoginPage.tsx`（账号/密码两栏；注册可含可选邮箱）。
4. **登录门禁**：`App.tsx` 据 token 存在与否在 `LoginPage` 与聊天界面间切换。
5. **替换硬编码 `user_id=1`**：
   - `client.ts` 的 `CURRENT_USER_ID` 改为从 `/auth/me` 或解码 token 得到（建议登录后调用 `/me` 缓存 id）。
   - `useChat.DEFAULT_USER_ID` 由登录用户 id 注入。
   - 文档/图谱/历史的 `?user_id=1` 全部改为真实 id（或直接去掉——路由改走 `CurrentUser` 后前端无需再传）。
6. **退出登录**：清 token + 回登录页。

> 前端契约为本期实现细节，详细交互以 PRD §6 为准；可与后端并行开发（mock token 先行）。

## 9. 数据迁移

`init_db()` 用 `create_all`，**不** ALTER 已有表，故：

- **开发/复现环境（推荐）**：删除 `backend/agentar.db`（及 `-wal/-shm`），重启由 `init_db()` 重建含新列的 `users`；测试用 `scripts/seed_users.py` 播种 2~3 个演示账号。
- **保留旧数据**：手动 `ALTER TABLE users ADD COLUMN ...`（见 §3.1），并对既有无密码假用户（`user_1` 等）要么删除、要么设一默认密码；因其不可登录，建议直接清掉。
- **生产环境**：引入 Alembic 迁移（非本期范围），不要靠 `create_all`。

`scripts/seed_users.py` 伪代码：
```python
for u, p in [("alice","alice1234"), ("bob","bob1234")]:
    if not get_by_username(u):
        create_user(UserCreate(username=u, password=p))
```

## 11. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 旧 `user_1` 假用户无密码无法登录 | 重置 dev DB + seed（§9） |
| `create_all` 不 ALTER | 显式 ALTER 或重建；生产用 Alembic |
| SECRET_KEY 误提交 | 仅 `${AUTH_SECRET_KEY}` 占位 + 缺失即启动失败 |
| localStorage token XSS | 本期接受（对齐模板）；后续迁 httpOnly Cookie |
| `get_db` 异步 vs 模板同步 | `get_current_user` 用 `await session.get` |
| 既有测试依赖 `user_id=1` 硬编码 | 改造端点后改用 seed 用户 + token |
