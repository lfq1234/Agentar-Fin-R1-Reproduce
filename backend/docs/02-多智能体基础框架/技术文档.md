## 1. 需求背景与目标

对应需求文档（v2）：在 01 模型层（`get_model()`）之上，搭建 AgentScope v1 的 **multi-agent 基础框架**——初始化运行时、定义 Coordinator + 5 领域专家 + 3 支撑角色（RAG / 审核 / 风控）、按流水线编排跑通一条对话，并具备结构化分析能力。

## 4. 数据结构（`app/agent/system.py`）

```python
from dataclasses import dataclass, field

@dataclass
class AgentResult:
    reply: str = ""                       # 领域专家的主回复（最终输出）
    compliance_notes: list[str] = field(default_factory=list)  # 审核：合规提示（建议式）
    risk_flags: list[str] = field(default_factory=list)        # 风控：风险警示（建议式）
    intent: str | None = None             # analyze 模式
    slots: dict[str, str] = field(default_factory=dict)
    tool_plan: list[str] = field(default_factory=list)
    expression: str = ""                  # 给前端的表达/话术
```
> `compliance_notes` / `risk_flags` 为**建议式**产物：审核 / 风控不阻断输出，仅附加提示与警示。

## 5. 运行入口（`app/agent/system.py`）

```python
async def run(
    message: str,
    scene: str | None = None,             # Banking/Securities/Insurance/Trust/MutualFunds
    structured: bool = False,             # True → 同时产出结构化分析
) -> AgentResult: ...
```

- `structured=False`：返回 `reply` + 建议式 `compliance_notes` / `risk_flags`。
- `structured=True`：在以上基础上填充 `intent/slots/tool_plan/expression`（框架内部产出，**本期不暴露 HTTP**）。
- 内部流程：`get_system()`（懒加载、带锁）→ `agentscope.init(...)` → `build_agents()` → **流水线**（RAG → 专家 → 审核 → 风控）→ 汇总 → `AgentResult`。

## 7. 智能体构建与编排（`app/agent/agents.py` + `system.py`）

```python
from agentscope.agents import DialogAgent

SCENES = ["Banking", "Securities", "Insurance", "Trust", "MutualFunds"]

def build_agents(cfg_name: str) -> dict:
    def mk(name, prompt_file):
        return DialogAgent(name=name, model_config_name=cfg_name, sys_prompt=_load(prompt_file))
    agents = {
        # —— 协调者 ——
        "coordinator": mk("Coordinator", "agent/prompts/coordinator.txt"),
        # —— 5 领域专家 ——
        "Banking":     mk("BankingExpert",     "agent/prompts/banking.txt"),
        "Securities":  mk("SecuritiesExpert",  "agent/prompts/securities.txt"),
        "Insurance":   mk("InsuranceExpert",   "agent/prompts/insurance.txt"),
        "Trust":       mk("TrustExpert",       "agent/prompts/trust.txt"),
        "MutualFunds": mk("MutualFundsExpert", "agent/prompts/mutualfunds.txt"),
        # —— 3 支撑角色 ——
        "rag":    mk("RAGRetriever", "agent/prompts/rag.txt"),       # 02 仅接口占位
        "review": mk("ComplianceReviewer", "agent/prompts/review.txt"),  # 建议式
        "risk":   mk("RiskController", "agent/prompts/risk.txt"),        # 建议式
    }
    return agents
```

**流水线编排（base 框架，协调者驱动，全流水线贯穿）**：
1. **路由**：若 `scene` 已给定 → 直送对应专家；否则先让 Coordinator 判定场景（意图识别）。
2. **RAG 检索（占位）**：`context = retrieve(message)`（02 返回 stub 空上下文）；将 `context` 注入领域专家的输入。
3. **领域专家作答**：`await expert(message, context)` → 答案 draft。
4. **审核（建议式）**：`await review(message, draft)` → `compliance_notes`（不阻断）。
5. **风控（建议式）**：`await risk(message, draft)` → `risk_flags`（不阻断）。
6. **汇总**：`reply = draft`；若 `structured=True` 另用 Coordinator 抽取 `intent/slots/tool_plan/expression`。

> 总文档 §7.2 提到的 `msghub` 作为消息中枢：base 框架先以"显式流水线"保证可跑通；`msghub` 多角色自组织对话作为后续增强（留排期），不影响本期验收。

## 9. 结构化分析（框架级）

- 由 Coordinator 持一份"分析指令"，要求模型按固定 JSON schema 输出：
  ```json
  {"intent": "...", "slots": {"字段":"值"}, "tool_plan": ["..."], "expression": "..."}
  ```
- `system.py` 解析 JSON → 填充 `AgentResult`；解析失败时降级（`intent=None`、其余空）。

## 10. 实现要点与步骤

1. **`agent/prompts/`**：写 9 个简版 system prompt（协调者负责路由/意图/流水线驱动；专家负责各自领域问答；rag 描述检索职责——02 占位；review 描述合规审查要点；risk 描述风险审查要点）。本期占位即可，后续细化。
2. **`agent/retrieval.py`**：`Passage` + `retrieve()` 占位实现。
3. **`agent/agents.py`**：`build_agents(cfg_name)` 构建 Coordinator + 5 专家 + RAG + 审核 + 风控。
4. **`agent/system.py`**：
   - `get_system()`：模块级懒初始化（带锁），避免每次调用重复 `agentscope.init`（其全局单例）。
   - `init_agent_system()`：`cfg = get_model().build_agentscope_config()` → `agentscope.init(...)`。
   - `build_agents()` 包装：构建 8 个角色。
   - `run(message, scene, structured)`：上面 §7 流水线，返回 `AgentResult`。
5. **`agent/__init__.py`**：导出 `run`、`AgentResult`、`Passage`。
6. **单测**（`tests/test_agent_framework.py`）：用 fake/mock 模型验证路由命中、流水线在 `retrieve()` 返回 stub 时跑通、结构化解析；无真实 key 时 `skip`。
