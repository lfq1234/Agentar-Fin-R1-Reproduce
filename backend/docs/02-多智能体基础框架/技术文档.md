## 1. 需求背景与目标

对应需求文档（v3）：在 01 模型层（`get_model()` + `generate()`）之上，搭建 AgentScope 的 **multi-agent 基础框架**——初始化运行时、定义 Coordinator + 5 领域专家 + 3 支撑角色（**信息查询智能体** / 审核 / 风控）、按流水线编排跑通一条对话，并具备结构化分析能力。其中"信息查询智能体"即原 RAG 角色（独立智能体，负责本地知识检索），其联网新闻能力由 **04** 扩展设计。

**本期只做框架本身**，主体位于 `app/agent/`，**不碰** `services/`（服务层）、`routes/`（接口层）、`db/`（数据层）。这些下游模块由后续独立需求来消费本框架。

**架构边界（评审 G1，已落定方案 X）**：02 对 LLM 的**每一次调用都必须经过 01 的统一调用方法 `get_model().generate()`**。AgentScope 在本框架中只承担多智能体编排/流水线职责；02 通过自定义模型包装器把模型执行委托给 01，禁止任何 agent 自行直连 OpenAI / 本地 vLLM。

## 4. 数据结构（`app/agent/system.py`）

```python
from dataclasses import dataclass, field

@dataclass
class AgentResult:
    reply: str = ""                       # 领域专家的主回复（最终输出）
    compliance_notes: list[str] = field(default_factory=list)  # 审核：合规提示（建议式）
    risk_flags: list[str] = field(default_factory=list)        # 风控：风险警示（建议式）
    intent: str | None = None             # analyze 模式
    slots: dict[str, str] = field(default_factory=dict)
    tool_plan: list[str] = field(default_factory=list)
    expression: str = ""                  # 给前端的表达/话术
```
> `compliance_notes` / `risk_flags` 为**建议式**产物：审核 / 风控不阻断输出，仅附加提示与警示。

## 5. 运行入口（`app/agent/system.py`）

```python
async def run(
    message: str,
    scene: str | None = None,             # Banking/Securities/Insurance/Trust/MutualFunds
    structured: bool = False,             # True → 同时产出结构化分析
) -> AgentResult: ...
```

- `structured=False`：返回 `reply` + 建议式 `compliance_notes` / `risk_flags`。
- `structured=True`：在以上基础上填充 `intent/slots/tool_plan/expression`（框架内部产出，**本期不暴露 HTTP**）。
- 内部流程：`get_system()`（懒加载、带锁）→ AgentScope 运行时初始化 → `build_agents()`（注入 01 包装器）→ **流水线**（信息查询智能体 → 专家 → 审核 → 风控）→ 汇总 → `AgentResult`。

## 6. 模型调用边界（评审 G1，方案 X：02 必须调用 01）

02 不自行初始化 AgentScope 的模型、不直连 OpenAI / vLLM。所有 LLM 调用都通过 01：

```python
from app.model import get_model
from app.agent.model_bridge import AgentarModel   # 02 自定义包装器
from app.model.exceptions import ModelInvokeError

# 1) 01 统一入口拿模型对象（api / local 由配置决定，对 02 透明）
model = get_model()

# 2) 包装成 AgentScope 可用的模型对象，但其 generate 实际委托给 01
agent_model = AgentarModel(model)

# 3) 智能体通过 model=包装器 注入，模型执行落到 01 的 generate()
#    ReActAgent(name=..., model=agent_model, service_toolkit=..., sys_prompt=...)   # 专家/审核/风控/信息查询智能体
#    DialogAgent(name=..., model=agent_model, sys_prompt=...)                       # 仅 Coordinator 路由
```

> `AgentarModel` 的契约：当 AgentScope 向它要一次补全时，它调用 `model.generate(prompt)`，
> 并把 `ModelInvokeError` 原样抛出（由上层 `run()` 捕获转化，见 §7 / 评审 N2）。
> 02 **不直接消费** `build_agentscope_config()` 做模型初始化；该方法的形态对齐是 01 的前置修改（见 §12），
> 仅作为 01 对下游（服务层等）的配置导出契约存在。
>
> **角色类型（v4 决策，用户确认）**：专家（5 领域专家）、审核、风控、信息查询智能体 **一律使用 `ReActAgent`**（带 `service_toolkit` 工具）；
> 仅 Coordinator 使用 `DialogAgent` 做路由 / 意图识别。即 9 个角色中 8 个为 `ReActAgent`、1 个为 `DialogAgent`。
>
> ⚠️ AgentScope 版本：**已锁定经典版 `agentscope==0.1.6`**（含 `ReActAgent` / `DialogAgent` / `ServiceToolkit` / `agentscope.init`）。

> 「包装器委托 `get_model().generate()`」这一边界不变（见 §12 / §13）。

## 7. 智能体构建与编排（`app/agent/agents.py` + `system.py` + `model_bridge.py`）

```python
from agentscope.agents import DialogAgent, ReActAgent
from app.model import get_model
from app.agent.model_bridge import AgentarModel
from app.agent.tools import build_toolkit

SCENES = ["Banking", "Securities", "Insurance", "Trust", "MutualFunds"]

# ReActAgent 子类：模型执行重定向到 01 的 generate()（专家/审核/风控/信息查询智能体 均用 ReActAgent）
class ReActAgentX(ReActAgent):
    def __init__(self, name, inner, sys_prompt, toolkit):
        super().__init__(name=name, model_config_name="agentar-placeholder",
                         service_toolkit=toolkit, sys_prompt=sys_prompt, verbose=False)
        self.model = AgentarModel(inner)   # 覆盖占位模型，改走 01

# DialogAgent 子类：仅 Coordinator 用于路由/意图识别
class DialogAgentX(DialogAgent):
    def __init__(self, name, inner, sys_prompt):
        super().__init__(name=name, model_config_name="agentar-placeholder",
                         sys_prompt=sys_prompt, verbose=False)
        self.model = AgentarModel(inner)

def build_agents(inner) -> dict:
    agents = {}
    # —— 协调者（DialogAgent） ——
    agents["coordinator"] = DialogAgentX("Coordinator", inner, _load("coordinator"))
    # —— 5 领域专家（ReActAgent，带 lookup_knowledge 工具） ——
    for scene in SCENES:
        agents[scene] = ReActAgentX(f"{scene}Expert", inner, _load(scene.lower()),
                                    build_toolkit(scene))
    # —— 3 支撑角色（ReActAgent，带各自工具） ——
    agents["rag"]    = ReActAgentX("RAGRetriever", inner, _load("rag"), build_toolkit("rag"))        # 02 仅接口占位（信息查询智能体：本地 RAG；联网新闻见 04）
    agents["review"] = ReActAgentX("ComplianceReviewer", inner, _load("review"), build_toolkit("review"))  # 建议式
    agents["risk"]   = ReActAgentX("RiskController", inner, _load("risk"), build_toolkit("risk"))        # 建议式
    return agents
```

**流水线编排（base 框架，协调者驱动，全流水线贯穿）**：
1. **路由**：若 `scene` 已给定 → 直送对应专家；否则先让 Coordinator 判定场景（意图识别）。
2. **信息查询智能体检索（占位）**：`context = retrieve(message)`（02 返回 stub 空上下文）；将 `context` 注入领域专家的输入。
3. **领域专家作答**：`await expert(message, context)` → 答案 draft。**模型调用经 `AgentarModel` → `get_model().generate()`（方案 X）**。
4. **审核（建议式）**：`await review(message, draft)` → `compliance_notes`（不阻断）。
5. **风控（建议式）**：`await risk(message, draft)` → `risk_flags`（不阻断）。
6. **汇总**：`reply = draft`；若 `structured=True` 另用 Coordinator 抽取 `intent/slots/tool_plan/expression`。

**异常桥接（评审 N2）**：`run()` 捕获来自 01 的 `ModelInvokeError`（key 缺失 / 网络错误 / 超时），转化为框架级错误并附到 `AgentResult` 或显式抛出，**不得静默吞掉**：

```python
from app.model.exceptions import ModelInvokeError

async def run(message, scene=None, structured=False) -> AgentResult:
    try:
        # ...流水线...
    except ModelInvokeError as exc:
        # 转为框架级错误：记录并抛出（或由调用方决定降级）
        raise ModelInvokeError(f"[02 多智能体] 模型调用失败: {exc}") from exc
```

> 总文档 §7.2 提到的 `msghub` 作为消息中枢：base 框架先以"显式流水线"保证可跑通；`msghub` 多角色自组织对话作为后续增强（留排期），不影响本期验收。

## 9. 结构化分析（框架级）

- 由 Coordinator 持一份"分析指令"，要求模型按固定 JSON schema 输出：
  ```json
  {"intent": "...", "slots": {"字段":"值"}, "tool_plan": ["..."], "expression": "..."}
  ```
- `system.py` 解析 JSON → 填充 `AgentResult`；解析失败时降级（`intent=None`、其余空）。

- **RAG 真实后端**：02 仅接口占位，真实向量库 / 知识库接入为后续独立需求；本期不阻塞。
- **与总文档层位差异**：总文档 §7 当前把多 Agent 编排放在 `services/agent_runtime.py` 且仅描述 5 专家拓扑；待 02 评审通过后回总文档校正：`app/agent/` 为编排归属，并补充 信息查询智能体 / 审核 / 风控 支撑角色。
