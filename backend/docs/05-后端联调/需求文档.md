## 1. 背景与目标

`Agentar-Fin-R1-Reproduce` 后端前四个模块已分别落地：

- **01-模型接口**：统一模型调用入口（`app/model/`），`get_model()` 文本生成 + `get_embedder()` 嵌入，均支持 api/local 双模式；模型不可用时抛 `ModelInvokeError`。
- **02-多智能体基础框架**：`app/agent/system.py` 的 `run()` 串起"路由→RAG→专家作答→审核→风控→结构化分析"，返回 `AgentResult`。
- **03-传统后端基础层**：`app/routes/chat.py` 暴露 `POST /api/v1/chat`、`POST /api/v1/analyze`、`GET /api/health`；`app/services/chat_service.py`、`analyze_service.py` **已 `await agent_run(...)` 接通 02 框架**，并以 SQLite（`aiosqlite`）持久化会话与消息。
- **04-专家智能体与工具 RAG**：02 之上的内容层——5 专家 + 审核 + 风控 + 信息查询 8 角色提示词，以及 `app/agent/retrieval.py` 的 RAG 七环节（ingest/parse/embed/store/search/news）。

**本模块（05-后端联调）不开发前端**，只在后端进程内把 01（模型）/ 02、04（Agent）/ 03（后端+DB）三层串起来做**端到端集成验证**，确认：

1. 真实或模拟环境下，`/api/v1/chat`、`/api/v1/analyze` 全链路可跑通；
2. 01 的模型/嵌入调用、04 的 RAG 检索、03 的落库在链路中确实生效；
3. 模型不可用时链路优雅降级（不崩溃、返回清晰错误）。

> 前端（如有）属独立模块，不在 05 范围。05 的"联调客户端"仅用 FastAPI `TestClient`、curl 或 `requests` 脚本驱动，**不涉及任何浏览器/UI 代码**。

**目标**：给出一份可执行的"后端联调手册 + 验收基线"，使"用户请求 → 03 路由 → 02/04 Agent 处理（应用 01 模型）→ SQLite 落库 → 结构化返回"在后端侧完全可见、可断言。

## 2. 范围

### 2.1 包含（In Scope）
- **模型联调（01）**：验证 `get_model()` / `get_embedder()` 在 api / local 两种模式下被 02/04 正确调用；验证 `ModelInvokeError` 能沿链路透传，后端返回可识别错误而非进程崩溃。
- **Agent 联调（02/04）**：验证 `app/agent/run()` 的全流程（路由→RAG→专家→审核→风控→结构化）在真实模型下产出正确 `AgentResult`；验证 04 的 `retrieval.py` 在 ingest 知识库后能命中并返回 passages。
- **后端联调（03）**：验证 `POST /api/v1/chat`、`POST /api/v1/analyze`、`GET /api/health` 经真实 FastAPI 进程跑通；验证 SQLite（`aiosqlite`）在 `db.enabled=true` 时落库 `conversations` / `messages`。
- **续聊一致性联调**：验证第二次 `/api/v1/chat` 带 `conversation_id` 时后端按同一会话追加消息（SQLite 同 `conversation_id`）。
- **结构化分析联调**：验证 `structured=True`（`/api/v1/analyze`）返回 `intent` / `slots` / `tool_plan` / `expression` 四字段。
- **降级/Stub 联调**：本机无可用模型或密钥时，可用 stub 开关验证"后端 + 落库 + 契约返回"链路（不进生产）。
- **RAG 端到端验证**：准备一份 sample 金融知识库文档，经 04 `ingest_*` 入库后，提问验证检索增强确实影响 `reply`（可断言 reply 含检索片段或引用）。

### 2.2 排除（Out of Scope）
- **任何前端 / UI 代码**（React、Vite、浏览器交互、页面渲染）——明确不属于 05。
- 模型训练、Agent 编排实现、RAG 检索实现本身（属 01/02/04，05 只验证不重做）。
- 流式（SSE）响应（本期后端为同步 JSON 响应）。
- 用户鉴权 / 多租户（后端 `user_id` 当前为请求体临时字段，非 token 解析）。

## 3. 联调目标（功能需求）

### 目标 1 · 健康检查联调
- `GET /api/health` 返回 `200 {"status":"ok"}`，确认后端进程与路由挂载正常。

### 目标 2 · 聊天主链路联调（模型 + Agent + 后端 + 落库）
- `POST /api/v1/chat` 请求体 `{message, scene?, user_id?, conversation_id?}`。
- 后端经 `chat_service` → `agent_run(message, scene, structured=False)` → 02/04 链路 → 返回 `ChatResponse{reply, conversation_id?, compliance_notes[], risk_flags[]}`。
- 当 `user_id` 非空且 `db.enabled=true`：SQLite 落库 User/Conversation/两条 Message。
- 断言：`reply` 非空；`compliance_notes` / `risk_flags` 为 `list[str]`（与 02/03/04 锁定契约一致）。

### 目标 3 · 分析链路联调（结构化）
- `POST /api/v1/analyze` 请求体 `{message, scene?}`。
- 后端经 `analyze_service` → `agent_run(message, scene, structured=True)` → 返回 `AnalyzeResponse{intent?, slots{}, tool_plan[], expression}`。
- 断言：四字段类型与契约一致；`tool_plan` 为列表、`slots` 为对象。

### 目标 4 · 模型不可用降级联调（01）
- 临时将 `model.api` 指向不可达端点（或清空 `OPENAI_API_KEY`）。
- 断言：链路**不崩溃**，后端返回可识别错误（4xx/5xx 带清晰 message，或 `reply` 内含降级提示）；`ModelInvokeError` 已被 02 `run()` 捕获（不会冒泡为 500 无信息）。

### 目标 5 · RAG 知识库命中联调（04）
- 准备 sample 知识库（如 `kb/sample_faq.md`，含若干金融条款文本）。
- 经 04 `ingest_document` / `ingest_text` 入库（向量由 01 `get_embedder()` 生成，存 SQLite）。
- 提及相关条款的问题，`POST /api/v1/chat` → 断言 `reply` 命中检索片段（或 `compliance_notes` 引用了该条款）。
- 验证领域过滤 / 生效日过滤在检索中生效（如 04 retrieval 设计）。

### 目标 6 · 续聊与落库一致性联调（03）
- 首次 `/api/v1/chat` 不带 `conversation_id` → 返回新 `conversation_id`。
- 第二次带该 `conversation_id` → 后端按同一会话处理；SQLite `messages` 表可见同 `conversation_id` 的多条记录。
- 断言：落库记录数随对话增长，且 `conversation_id` 一致。

## 4. 联调契约（对齐 01/02/03/04 已锁定接口）

> 05 不新定义任何契约，仅消费以下已锁定接口。

### 4.1 模型层（01）
- `from app.model import get_model, get_embedder`。
- 文本生成：`get_model()` → `generate(prompt)` → `str`；api 缺 key / 网络不可达抛 `ModelInvokeError`。
- 嵌入：`get_embedder()` → `embed(texts: list[str])` → `list[list[float]]`；配置段 `emb.mode ∈ {api, local}`。
- 配置：`config.yaml` 顶层 `model`（api/local）+ `emb`（api/local），`api_key` 支持 `${ENV}` 替换。

### 4.2 Agent 层（02/04）
- `from app.agent import run`；`await run(message: str, scene: str|None, structured: bool) -> AgentResult`。
- `AgentResult` 字段：`reply: str`、`compliance_notes: list[str]`、`risk_flags: list[str]`、`intent: str|None`、`slots: dict`、`tool_plan: list[str]`、`expression: str`。
- 场景枚举（与 `app/agent/prompts/*` 对齐）：`Banking` / `Securities` / `Insurance` / `Trust` / `MutualFunds`（缺省 `Banking`）。

### 4.3 后端层（03）
- `GET /api/health` → `{"status":"ok"}`。
- `POST /api/v1/chat` → `ChatRequest` / `ChatResponse`（§3 目标 2 字段）。
- `POST /api/v1/analyze` → `AnalyzeRequest` / `AnalyzeResponse`（§3 目标 3 字段）。
- 数据库：SQLite（`config.db.type=sqlite`，异步 `aiosqlite`，库文件默认 `./agentar.db`）；表 `users` / `conversations` / `messages`。

---

## 5. 配置（联调环境）

- **01 模型**：`model.mode = api`（需 `OPENAI_API_KEY` 环境变量）或 `local`（vLLM `/v1`，如本机已起 vLLM）。
- **01 嵌入**：`emb.mode = api`（需 `OPENAI_API_KEY`）或 `local`（本地嵌入服务 `/v1`）。
- **03 数据库**：`config/config.yaml` 设 `db.enabled: true`、`db.type: sqlite`（库文件默认 `./agentar.db`）。
- **03 CORS**：`config.server.cors.origins`，联调期可放行联调客户端主机（TestClient 无需跨域）。

## 6. 验收标准（后端视角，不涉及前端）

- [ ] 后端可启动（`uvicorn app.main:app --port 8000`），lifespan 调 `init_db()` 建表。
- [ ] `GET /api/health` → `200 {"status":"ok"}`。
- [ ] `POST /api/v1/chat` 返回 `reply` + `conversation_id`（带 user_id 时）+ `compliance_notes` + `risk_flags`；`reply` 非空。
- [ ] `POST /api/v1/analyze` 返回 `intent` / `slots` / `tool_plan` / `expression`，类型与契约一致。
- [ ] 模型不可用时链路不崩溃，返回清晰错误（降级）。
- [ ] SQLite 落库：联调后 `agentar.db` 的 `conversations` / `messages` 有对应记录；续聊 `conversation_id` 一致。
- [ ] RAG 命中：ingest sample 后相关提问，`reply` 含检索内容或引用（断言命中）。
- [ ] 集成测试（`tests/test_integration_*.py`，用 `TestClient`）覆盖上述链路，CI 可跑。
- [ ] 所有断言不依赖前端；联调客户端仅用 TestClient / curl / requests。
